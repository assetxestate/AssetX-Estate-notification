# คลิปของคอนเทนต์และการส่งขึ้นเพจเป็น Reel

เจ้าของขอ 24 พ.ย. 2569 หลังทำคลิป #32 เสร็จ: ให้แนบคลิปกับโพสต์ในหน้าการตลาด และส่งขึ้นเพจ Facebook ได้จากในแอป (เดิมระบบส่งได้แค่ข้อความกับรูป)

## ใช้ยังไง

1. หน้าการตลาด → เครื่องมือ → ทำวิดีโอ → เลือกคอนเทนต์ (หรือ `/marketing?video=<เลขคอนเทนต์>`) — ต้องเปิดธง `MARKETING_PROOF_CARDS`
2. แผง "คลิปที่ตัดต่อเสร็จ" → เลือกไฟล์คลิป (.mp4 ไม่เกิน 50 MB) → ระบบอัปโหลด อ่านกลับมาเทียบขนาด แล้วผูกกับโพสต์
3. ดูคลิปได้จากปุ่ม ดูคลิป (ลิงก์ชั่วคราว 1 ชั่วโมง)
4. ส่งขึ้นเพจ: ตรวจข้อความใต้คลิป (ตั้งต้นจากแคปชั่นของโพสต์) → ติ๊กถ้าคลิปมีภาพหรือเสียงจาก AI → กด เผยแพร่เป็น Reel บนเพจ → ยืนยันในกล่องถาม
5. Facebook ใช้เวลาประมวลผล กด ตรวจสถานะกับ Facebook จนขึ้นว่า เผยแพร่บนเพจแล้ว พร้อมลิงก์

## ทำงานยังไง

| ส่วน | ไฟล์ |
|---|---|
| ตรรกะล้วน (ตรวจไฟล์ ด่านข้อความ ย่อสถานะ) | `src/lib/marketingClip.js` |
| API หลังล็อกอิน `/api/marketing-clip` (feature `clip` ของ `api/marketing.js`) | `server/marketing-clip.js` |
| หน้าจอ | `src/components/ClipPanel.jsx` (อยู่ใน `VideoStudio.jsx`) |

- **ที่เก็บไฟล์:** bucket ปิด `marketing-clips` สร้างเองครั้งแรก ไม่มีตารางใหม่ ไม่ต้องรัน SQL · ปิดด้วย `MARKETING_CLIP_STORAGE=off`
- **อัปโหลด:** คลิปใหญ่เกินเพดานคำขอของเซิร์ฟเวอร์ (4.5 MB) จึงไม่ผ่านฟังก์ชัน — เซิร์ฟเวอร์ออกลิงก์อัปโหลดแบบเซ็นชื่อ (`createSignedUploadUrl`) แล้วเบราว์เซอร์ส่งไฟล์ตรงเข้าที่เก็บ (`uploadToSignedUrl`)
- **เพดาน 50 MB:** เป็นเพดานไฟล์ของที่เก็บไฟล์ในโปรเจกต์ Supabase นี้ (สร้าง bucket ที่ 100 MB ถูกปฏิเสธ)
- **ชื่อไฟล์:** `clips/c<เลขคอนเทนต์>-<เวลา>.mp4` ไม่เขียนทับ ไม่ลบ · เปลี่ยนไฟล์ = ไฟล์ใหม่ชื่อใหม่ ไฟล์เดิมยังอยู่
- **เวิร์กสเปซ:** เก็บแค่ `post.clip` = ตำแหน่งไฟล์ ขนาด ความยาว และ `post.clip.reel` = รหัสวิดีโอ สถานะ ลิงก์ · ไม่อยู่ในแฮชการอนุมัติ และการบันทึกไม่รีเซ็ตสถานะอนุมัติของโพสต์
- **ส่ง Reel (Reels Publishing API):** `reel-upload` เปิดรายการ (`upload_phase=start`) แล้วให้ Facebook ดึงไฟล์เองจากลิงก์ชั่วคราว 2 ชั่วโมง (header `file_url`) → `reel-publish` ส่ง `upload_phase=finish` + `video_state=PUBLISHED` + ข้อความ (+ `is_ai_generated`) · ไฟล์ไม่ผ่านเซิร์ฟเวอร์ของเรา
- **แทนที่คลิปหลังส่งแล้ว:** ปุ่ม แทนที่ด้วยคลิปใหม่ → หน้าจอเตือนว่า Reel เดิมยังอยู่บน Facebook (ระบบลบให้ไม่ได้ ต้องลบเอง) → เลือกไฟล์ใหม่ · Reel เดิมถูกเก็บใน `post.clip.previous` (5 รายการล่าสุด) พร้อมลิงก์ให้ไปลบ (`replaceClip`)
- **ขั้นยืนยัน:** อยู่ในหน้าเว็บ ไม่ใช้ `window.confirm` เพราะแผงเบราว์เซอร์ของแอป Claude ปิดกล่องแบบนั้นเองทันที
- **กันโพสต์ซ้ำ:** รหัสวิดีโอถูกบันทึกทันทีหลังส่งไฟล์ ถ้าขั้นเผยแพร่ล้ม กดอีกครั้งจะไม่ส่งไฟล์ซ้ำ · เผยแพร่แล้วหน้าจอไม่มีปุ่มส่งและปุ่มเปลี่ยนไฟล์อีก

## ด่านก่อนเผยแพร่

- ข้อความใต้คลิปผ่านด่านคำของแบรนด์ชุดเดียวกับแคปชั่น (`checkText`) ทั้งที่หน้าจอและที่เซิร์ฟเวอร์
- เซิร์ฟเวอร์ไม่เผยแพร่ถ้าไม่มี `confirmed: true` (หน้าจอส่งหลังคนกดยืนยันในกล่องถาม)
- **ยังไม่มี:** Reel ไม่ผ่านบันทึกการอนุมัติแบบแฮช (`assertApprovedForPublish` ผูกกับโพสต์ข้อความ/รูป) — ข้อความใต้คลิปที่แก้เองในแผงนี้จึงไม่ถูกเทียบกับฉบับที่อนุมัติ หน้าจอเตือนเรื่องนี้
- **ยังไม่มี:** ตั้งเวลา Reel และการนับเพดาน 30 โพสต์ต่อ 24 ชั่วโมงของ API

## ข้อกำหนดของ Reels (เอกสาร Meta อ่าน 24 พ.ย. 2569)

แนวตั้ง 9:16 · 3–90 วินาที · อย่างน้อย 540x960 (แนะนำ 1080x1920) · 24–60 เฟรมต่อวินาที · .mp4 · หน้าจอเตือนเมื่อไฟล์ไม่เข้าเกณฑ์ (ไม่บล็อก Facebook เป็นคนตัดสิน)
สิทธิของโทเคนเพจ: `pages_show_list` · `pages_read_engagement` · `pages_manage_posts` (ชุดเดียวกับการโพสต์เดิม)

## กติกาเรื่องเนื้อหา

- ส่งได้เฉพาะคลิปการตลาด ห้ามคลิปที่มีรูปโฉนดจริง รูปทรัพย์ของลูกค้า หรือข้อมูลลูกค้า
- คลิปที่มีภาพหรือเสียงจาก AI ต้องติ๊กแจ้ง Facebook (ค่าเริ่มต้นติ๊กไว้)

## ทดสอบ

- `npm run test:marketing-proof` (รวม `src/lib/marketingClip.test.mjs` และ `server/marketing-clip.test.mjs`)
- ตรวจหน้าจอด้วยเบราว์เซอร์จริง ที่เก็บและ Facebook จำลอง: เปิด vite ที่พอร์ต 5177 แล้ว `node .local/clip-e2e/run.mjs`
- ตรวจที่เก็บไฟล์กับ Supabase จริง (ไม่แตะ Facebook): `node .local/clip-e2e/storage-check.mjs <ไฟล์ mp4 เล็ก>`
- การส่ง Reel จริงทดสอบได้บน production เท่านั้น (เครื่องนี้ไม่มีโทเคน Meta)
