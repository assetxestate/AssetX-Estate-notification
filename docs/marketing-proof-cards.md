# Content Brief + Proof Card + ด่านอนุมัติฝั่งเซิร์ฟเวอร์ (/marketing)

เฟส P0 ของงาน "Original Content Intelligence System" (บรีฟในโฟลเดอร์ `ASSETX_MARKETING_AI_IMPLEMENTATION_HANDOFF/`) · เขียน 23 พ.ย. 2569

สถานะ: โค้ดและเทสต์เสร็จ · **ยังไม่ได้เปิดใช้** (ธงปิด ตารางยังไม่ได้สร้างใน Supabase ยังไม่ได้ deploy)

## ทำอะไร

เดิม: หัวข้อ → ระบบร่าง → คนกดอนุมัติ → โพสต์ · ด่านโพสต์ฝั่งเซิร์ฟเวอร์เชื่อสถานะ "ผ่านการตรวจ" ที่เบราว์เซอร์ส่งมา

ใหม่ (เมื่อเปิดธง):

1. **สร้างจากข้อมูลจริง** — ใน Studio มีแผงบรีฟ: หัวข้อ ปัญหาคนอ่าน ข้อสังเกตเฉพาะ บันทึกหน้างาน (วันที่สำรวจ ข้อสังเกต สิ่งที่ยังไม่ทราบ ชนิดราคา) กรอกเท่าที่มี
2. **Proof Card** — แหล่งข้อมูล (ชนิด ลิงก์ วันที่ตรวจ สิทธิเผยแพร่) และข้ออ้าง (ประเภทหลักฐาน 7 แบบ หมวด ข้อจำกัด ถ้อยคำที่เผยแพร่ได้) ผูกข้ออ้างกับแหล่ง แล้วคนกด "ยืนยันแล้ว"
3. **ร่างจากข้อมูลนี้** — ระบบเรียงข้อความจากข้อมูลที่กรอกและข้ออ้างที่ยืนยันแล้วเท่านั้น ไม่ใช้ AI ไม่เติมตัวเลขหรือเคส ข้ออ้างที่ยังไม่ยืนยันไม่ถูกเขียนลงร่าง
4. **ด่านตรวจแยกหมวด** — ถ้อยคำ/กฎหมาย · หลักฐาน · ข้อมูลส่วนบุคคล (สามหมวดนี้บล็อก) · ข้อสังเกตให้ผู้ตรวจ (ไม่บล็อก)
5. **อนุมัติผ่านเซิร์ฟเวอร์** — เซิร์ฟเวอร์ตรวจด่านเอง เก็บชื่อผู้ตรวจ เวลา และแฮชของเนื้อหา ติดตัวบล็อก = ไม่อนุมัติ
6. **ด่านส่งออก Facebook** — ต้องมีบันทึกอนุมัติที่แฮชตรงกับข้อความ ภาพ และข้ออ้าง ณ ตอนส่ง และตรวจหลักฐานซ้ำ (หมดอายุ/ถอนสิทธิหลังอนุมัติ = ส่งไม่ได้)

โหมดสร้างเร็ว (พิมพ์หัวข้ออย่างเดียว) ยังอยู่ โพสต์แบบนี้ไม่มี Proof Card ด่านบอกผู้ตรวจว่าเป็นความรู้ทั่วไป ต้องตรวจข้อเท็จจริงเอง แต่ยังต้องอนุมัติผ่านเซิร์ฟเวอร์เหมือนกัน

## ให้ AI เขียนจากโน้ต (เพิ่ม 23 พ.ย. 2569)

ร่างที่ระบบเรียงเองอ่านแข็ง เจ้าของจึงขอให้ AI เขียนจากโน้ตแทน ปุ่ม "ให้ AI เขียนจากโน้ตนี้" ในแผงบรีฟส่งงานเข้าคิว ตัวรับงานบนคอมสำนักงานให้ Codex เขียน 3 มุม (หักความเชื่อ ถอดวิธีคิด เช็กลิสต์ตรวจเอง) ราว 1 นาที แล้วหน้าเว็บแสดงให้เลือก ปุ่ม "เรียงร่างเอง (ไม่ใช้ AI)" ยังอยู่

- ส่งให้ AI เฉพาะข้อความที่คนกรอกและข้ออ้างที่ยืนยันแล้วและเลือกใช้ในโพสต์ ผ่านตัวลบข้อมูลบุคคลก่อน ข้ออ้างที่ยังไม่ยืนยันและแหล่งที่ไม่มีสิทธิเผยแพร่ไม่ถูกส่ง
- ทุกร่างผ่านด่านที่ไม่ใช้ AI ก่อนถึงหน้าเว็บ ร่างที่ไม่ผ่านถูกคัดออก:
  - ตัวเลขทุกตัวในร่างต้องมีในโน้ต (จำนวนนับไม่เกิน 10 ที่ไม่มีหน่วย เช่น "3 เรื่อง" ไม่นับ)
  - ต้องอ้างรหัสข้อเท็จจริงที่มีจริงในโน้ต
  - ด่านคำของแบรนด์ และด่านหลักฐาน/ข้อมูลส่วนบุคคลชุดเดียวกับตอนอนุมัติ
  - สองมุมที่คล้ายกันเกินไปนับเป็นมุมเดียว
- ด่านจับตัวเลขและข้ออ้างที่แต่งเพิ่มได้ แต่จับการตีความเกินโน้ตด้วยคำพูดไม่ได้ ร่างจึงยังต้องให้คนอ่านเทียบกับโน้ตและอนุมัติ
- ต้องรัน `supabase_marketing_brief_jobs.sql` หนึ่งครั้ง และเปิดตัวรับงานรุ่นใหม่บนคอมสำนักงาน ยังไม่รัน = ปุ่มแจ้งว่ายังไม่ได้ติดตั้งคิว ส่วนอื่นใช้ได้ตามเดิม
- ไฟล์: `server/briefWriter.js` (คำสั่งถึง AI ด่านตรวจ คิว ลูปของตัวรับงาน) · `server/briefWriter.test.mjs` · ลองกับ AI จริงโดยไม่แตะฐานข้อมูล: `node .local/proof-e2e/try-writer.mjs`

## กติกาของด่านหลักฐาน

| กรณี | ผล |
|---|---|
| ข้ออ้างที่เลือก "ใช้ในโพสต์" แต่ยังไม่ยืนยัน | บล็อก |
| ข้ออ้างที่ยังไม่ยืนยันหรือถูกปฏิเสธ แต่ข้อความไปอยู่ในแคปชั่น (เทียบชุดอักษร 3 ตัว ซ้ำ ≥ 70%) | บล็อก |
| ข้ออ้างยืนยันแล้ว แต่ไม่มีแหล่ง ไม่มีวันที่ตรวจ หรือแหล่งไม่ได้รับอนุญาตเผยแพร่ | บล็อก |
| หลักฐานเลยวันหมดอายุ | บล็อก |
| ราคาเสนอขายที่โพสต์ไม่เขียนกำกับว่า "ราคาเสนอขาย" · ตัวอย่างสมมติที่ไม่เขียน "สมมติ" | บล็อก |
| โพสต์พูดถึงราคาซื้อขายจริง/ปิดการขาย โดยไม่มีข้ออ้างประเภทราคาซื้อขายจริงที่ยืนยันแล้ว | บล็อก |
| มีตัวเลขอัตราดอกเบี้ย/ประโยชน์ตอบแทน ในโพสต์ที่มีบรีฟ แต่ไม่มีข้ออ้างหมวดกฎหมาย/ราคาที่ยืนยันรองรับ | บล็อก |
| เบอร์โทร เลขบัตร 13 หลัก เลขเอกสารสิทธิ์ พิกัด ชื่อบุคคล LINE ID อีเมล (ช่องทางของบริษัทไม่นับ) | บล็อก |

แหล่งชนิดราชการ ประกาศขาย และรายงานภายนอก เริ่มที่ "อนุญาตเผยแพร่แล้ว" (อ้างถึงแหล่งสาธารณะ) · ของเราเองและเอกสารธุรกรรมเริ่มที่ "ยังไม่ทราบ" ซึ่งใช้สาธารณะไม่ได้

อัตราดอกเบี้ย: ระบบไม่ตัดสินว่าอัตราใดถูกกฎหมาย (`RATE_POLICY` โหมด `manual_review`) เพดานต่างกันตามประเภทสัญญา ทรัพย์ และคู่สัญญา ผู้ตรวจต้องเทียบกับตัวบทเป็นรายกรณี

## การเปิดใช้ (ยังไม่ได้ทำ ต้องให้เจ้าของสั่ง)

1. รัน `supabase_marketing_proof.sql` ใน Supabase SQL Editor (เพิ่มตารางอย่างเดียว รันซ้ำได้)
2. ตั้ง `MARKETING_PROOF_CARDS=1` ใน Vercel แล้ว deploy
3. เปิด /marketing → Studio ต้องมีแผง "สร้างจากข้อมูลจริง" · แท็บ ร่าง มีช่องชื่อผู้ตรวจและปุ่ม "ตรวจหลักฐาน"
4. ทดสอบหนึ่งรอบด้วยข้อมูลสมมติ: บรีฟ → แหล่ง → ข้ออ้าง → ยืนยัน → ร่าง → อนุมัติ (ยังไม่ต้องกดส่ง Facebook)

ผลของการเปิดธงที่ต้องรู้ก่อน:

- โพสต์ที่อนุมัติไว้ก่อนเปิดธงและยังไม่ได้ส่ง จะส่งไม่ได้จนกว่าจะย้ายกลับแท็บ ร่าง แล้วอนุมัติใหม่ (ไม่มีบันทึกอนุมัติฝั่งเซิร์ฟเวอร์) · โพสต์ที่ส่งหรือตั้งเวลาบน Facebook ไปแล้วไม่กระทบ
- เปิดธงแต่ยังไม่ได้สร้างตาราง = ส่ง Facebook จากหน้านี้ไม่ได้ (ตั้งใจให้ปิดไว้ก่อน) หน้าเว็บขึ้นข้อความเตือน

ยกเลิก: ลบ `MARKETING_PROOF_CARDS` แล้ว deploy ระบบกลับเป็นแบบเดิมทันที ตารางไม่ต้องลบ

## ข้อจำกัดที่รู้

- แอปมีบัญชีเดียว ไม่มีรหัสผู้ใช้: "ผู้ตรวจ" คือชื่อที่พิมพ์เอง ไม่ได้พิสูจน์ตัวตน
- การอนุมัติผูกกับรหัสของภาพ (`mediaAssetId`) ไม่ใช่เนื้อไฟล์ภาพ
- การจับว่าข้ออ้างอยู่ในแคปชั่นใช้การเทียบชุดอักษร เขียนใหม่ด้วยคำอื่นทั้งประโยคจะไม่ถูกจับ ผู้ตรวจยังต้องอ่าน
- บรีฟรูปและแฮชแท็กของร่างจากบรีฟยังมาจากแม่แบบหัวข้อ (สื่อจากข้อเท็จจริงของร่างเป็นงานเฟส P2)
- ช่องทางที่บันทึกการโพสต์เอง (คัดลอกไปวาง) ยังตรวจฝั่งหน้าเว็บเท่านั้น
- ยังไม่มีการอัปโหลดไฟล์หลักฐาน: แหล่งเก็บเป็นลิงก์หรือชื่อไฟล์อ้างอิง
- เวิร์กสเปซของ /marketing ยังเป็นก้อนเดียวที่เครื่องล่าสุดเขียนทับ (ของเดิม) · ข้อมูลหลักฐานอยู่ตารางแยกและมีเลขเวอร์ชันกันเขียนทับ
