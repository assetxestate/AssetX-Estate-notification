# ระบบออกแบบ Hook (ประโยคเปิด + พาดหัว)

เจ้าของสั่งเมื่อ 9 พ.ย. 2569 ว่า "ทำระบบการออกแบบ Hook ให้อ่านแล้วชวนให้หยุดและน่าอ่านต่อ… รีเสิร์ชคลิปหรือคอนเทนต์บนโซเชียลที่เป็นไวรัล มาปรับประยุกต์ให้เป็นในแบบฉบับของเรา"

## ปัญหาที่วัดได้ก่อนทำ

สำรวจร่าง AI ทั้ง 58 ชิ้นที่มีอยู่ (`.local/hook-survey.mjs`) แล้วพบปัญหา 2 อย่าง:

- **พาดหัวเป็นป้ายชื่อเรื่อง ไม่ใช่ hook** เช่น "รับจำนอง ต้องเช็กสิทธิ" "เตรียมเอกสาร ก่อนจำนอง" "ขายฝาก ตรวจเงื่อนไข 4 จุด"
- **ประโยคเปิดวนอยู่ 3 แม่แบบ** ทั้ง 3 แบบบอกว่าเรื่องคืออะไร แต่ไม่ให้เหตุผลว่าทำไมต้องอ่านต่อ
  - "ถ้าคุณกำลัง… มี N ข้อให้เช็ก…"
  - "เคสสมมุติ: …"
  - "ธนาคารแห่งประเทศไทย (ธปท.) แถลงข่าว…"

## รีเสิร์ช: ของที่แรงจริงในตลาดไทย

**1. ชื่อคลิปของช่อง YouTube ที่ระบบเฝ้าอยู่**

ใช้ RSS วันที่ 9 พ.ย. 2569 แล้ววัดวิวเทียบค่ากลางของช่องตัวเอง ช่องใหญ่กับช่องเล็กจึงเทียบกันได้

| รูปแบบ | ตัวอย่างชื่อคลิป | เท่าของค่ากลางช่อง |
|---|---|---|
| ข้อกฎหมายที่แย้งความเชื่อ | เรื่องสิทธิครอบครองห้องชุดของเจ้าของห้อง | 9.3 |
| ผลก่อน แล้วตามด้วย "เพราะ…" | ทุบบ้านเพราะที่ดินส่วนกลาง · พี่น้องตัดขาดเพราะมรดก | 3.2–3.3 |
| เปิดโปงกลโกง | การถือครองบ้านผ่านทรัพย์อิงสิทธิ | 6.2 |
| สถานการณ์เจาะจง | กู้ร่วมกับแฟนแต่ไม่จดทะเบียนสมรส | 5.3 |
| ย้อนแย้งแล้วถามว่าทำไม | เงินเดือนขึ้นทุกปี แต่ทำไม… | 3.9 |

**2. รีเสิร์ชเว็บ: ชื่อคลิปไทยเรื่องหนี้ บ้าน ที่ดิน และขายฝาก 28 คลิป**

เปิดหน้าดูวิวจริงทุกคลิป สูตรที่ซ้ำกันในคลิปที่วิวสูงมีดังนี้:

| สูตร | ตัวอย่างชื่อคลิป | วิว |
|---|---|---|
| สถานการณ์ก่อน แล้ว "ทำยังไง" (พบบ่อยที่สุดในช่องทนาย/การเงิน) | "ถูกฟ้อง ไม่ได้ไปศาล ไม่มีทรัพย์สินให้ยึด ทำไงได้บ้าง?" | 362K |
| เตือนพร้อมบอกว่าเตือนใคร | "ค้ำรถ ค้ำเงินกู้ อย่าเพิ่งยอมจ่าย… ผู้ค้ำประกันควรรู้" | 3.2M |
| เช็กความเชื่อ "…จริงไหม" | "เมื่อลูกหนี้ตาย หนี้จะจบไปด้วยจริงมั๊ย" | 469K |
| | "10 อย่างที่กรมบังคับคดีบังคับใช้หนี้ไม่ได้" | 911K |
| ทำแบบไหนถึงจะไม่เสีย | "อยากซื้อขายที่ดิน ต้องทำแบบไหน ถึงจะไม่เสียโง่" | 498K |
| เทียบ A กับ B | "จำนอง vs. ขายฝาก ต่างกันอย่างไร" | 70K |

- **เพดานของหัวข้อ:** คลิปเรื่องขายฝากโดยตรงตันที่ราว 100K วิว แต่เรื่องเสียบ้าน ถูกยึด หรือถูกฟ้อง ไปได้ถึง 0.2–3M วิว จึงควรผูกเรื่องขายฝากเข้ากับความกังวลใหญ่เหล่านี้เมื่อข้อเท็จจริงรองรับ
- **Facebook และ TikTok:** อ่านจากเว็บไม่ได้ (ติดล็อกอินและด่าน JavaScript) ข้อมูล Facebook จึงมาจากตัวเฝ้าเพจของเราเอง

**3. งานวิจัยและแนวทางของแพลตฟอร์ม**

| เรื่อง | ผลที่พบ | ที่มา |
|---|---|---|
| คำเชิงลบในพาดหัว | ทุกคำเพิ่มคลิก 2.3% แต่คำที่ทำให้กลัวกลับลดคลิก | Robertson et al. 2023, Nature Human Behaviour, 12,448 การทดลองของ Upworthy |

**4. ข้อสังเกตจากแอดคู่แข่งที่ยิงนาน**

แอดที่สัญญาผลลัพธ์ เช่น "ได้เงินไว" "อนุมัติไว" มีสัดส่วนสูงในกลุ่มแอดที่ยิงนาน แต่เราไม่ใช้สูตรนี้ เพราะผิดกติกาแบรนด์และเสี่ยง ม.22

**ข้อจำกัดของรีเสิร์ช:** วิวขึ้นกับขนาดช่อง อายุคลิป และการซื้อโฆษณา ข้อมูลชุดนี้บอกว่าอะไร "แรง" แต่พิสูจน์ไม่ได้ว่าแรงเพราะ hook

## ระบบทำงานอย่างไร

**1. คลังสูตร (`research/hook_patterns.json`)**

มี 13 สูตร:

- ความเข้าใจผิดที่คนเชื่อกัน (ต้องมีข้อเท็จจริงไว้หัก)
- ผลก่อน เหตุทีหลัง
- ทำแบบไหนถึงจะไม่เสีย
- สัญญาณอันตราย (เฉพาะโครงเตือนภัย)
- สถานการณ์เจาะจง
- ทำได้ไหม
- ย้อนแย้งแล้วถามว่าทำไม
- เช็กจุดที่จับต้องได้
- เงินที่ต้องเตรียมจริง
- สองทางเลือกที่คนสับสน
- ข่าวนี้แปลว่าอะไรกับคนที่… (เฉพาะโครงข่าว)
- ประโยคที่ได้ยินแล้วต้องหยุดคิด (สูตรทดลอง หมุนน้อยกว่าสูตรอื่น)
- นับถอยหลังก่อนวันสำคัญ

ทุกสูตรมีวิธีเขียน พาดหัวคู่ ตัวอย่างโครง และหลักฐาน ฟิลด์หลักฐานไม่ถูกส่งเข้าพรอมต์ ส่วน `rules` คือกติกาที่ทุก hook ต้องผ่าน

**2. เลือกสูตร (`server/research/hooks.js` → `pickHookPatterns`)**

- ทุกมุมได้ 3 สูตรที่เข้ากับโครงโพสต์ (เช็กลิสต์ ถามตอบ เคสสมมุติ เตือนภัย ข่าว ให้ความรู้) และพยายามให้ต่างตระกูลกัน
- ไม่ซ้ำสูตรที่มุมอื่นของเรื่องเดียวกันใช้ไปแล้ว
- สูตรที่ร่างก่อนหน้าในรอบเพิ่งใช้ จะถูกลดน้ำหนักลงทีละ 25%
- บทเรียนจากของไวรัลปรับน้ำหนักได้ 0.6–1.8 เท่า และต้องมีตัวอย่างอย่างน้อย 5 ชิ้นก่อน

**3. คำสั่งในพรอมต์ (`hookPromptLines`)**

ผู้เขียน (Codex หรือ Ollama) ต้องเขียนประโยคเปิด 3 แบบ แบบละสูตร แต่ละแบบมีพาดหัวคู่ จากนั้นเลือกแบบที่ดีที่สุดเป็นบรรทัดแรกของแคปชั่น โครงโพสต์ทั้ง 6 แบบเปลี่ยนให้บรรทัดแรกเป็น hook เสมอ:

- **เคสสมมุติ:** ย้ายคำว่า "เคสสมมุติ:" ลงไปบรรทัดที่สอง ถ้าผู้เขียนลืม ระบบเติม "(เคสสมมุติ)" ให้เอง
- **ถามตอบ:** ไม่เปิดด้วย "ถาม:"
- **ข่าว:** เปิดด้วยผลต่อคนอ่าน ไม่ใช่ชื่อหน่วยงาน

**4. ตรวจและให้คะแนน (`parseHooks` / `scoreHook` / `hookIssue`)**

ไม่ใช้ AI ในขั้นนี้ จึงตรวจสอบย้อนได้ทุกขั้น

- **ปัดตก ถ้าเจอข้อใดข้อหนึ่ง:**
  - คำเร้าแบบคลิกเบต
  - ขอยอด
  - ระบุสถานะการเงินของคนอ่าน ("ถ้าคุณมีหนี้…" แบบมีเงื่อนไขผ่านได้)
  - ความเร่งแบบโปรโมชั่น
  - อ้างเคสจริงหรือลูกค้าของเรา
  - เปิดด้วยชื่อแบรนด์
  - ด่านเดียวกับแคปชั่น: คำต้องห้าม สัญญาผลลัพธ์ นิยามขายฝากผิด ชื่อเพจต้นทาง ลอกข้อความคู่แข่ง
  - ถ้าบรรทัดแรกของแคปชั่นติดด่าน ระบบสั่งร่างใหม่ทั้งชิ้น
- **คะแนน 0–100:**

  | เกณฑ์ | คะแนน |
  |---|---|
  | สั้น ≤ 90 ตัวอักษร | +15 |
  | คำสำคัญอยู่ใน 40 ตัวแรก | +15 |
  | เจาะจง (เอกสาร ขั้นตอน หรือตัวเลข) | +15 |
  | มีคำถาม ความขัดแย้ง หรือสัญญาประโยชน์ที่จับต้องได้ | +20 |
  | ชี้บทบาทคนอ่าน | +5 |
  | บอกสิ่งที่อาจเสียจริง | +5 |
  | เนื้อหาตอบสิ่งที่ hook สัญญา | +15 |
  | เนื้อหาไม่ตอบ (เสี่ยงคลิกเบต) | −20 |
  | แม่แบบเดิม | −15 |
  | คล้ายร่างอื่น | −15 |
- **ร่างใหม่เมื่อคะแนนต่ำ:** ถ้าคะแนนต่ำกว่า 45 ระบบร่างใหม่ 1 ครั้งพร้อมบอกเหตุผล ร่างแรกเก็บไว้เป็นสำรอง จึงไม่ทิ้งงาน
- **คำเตือนในร่าง:**
  - hook อ่อน
  - มีทางเลือกคะแนนสูงกว่าอย่างน้อย 15
  - พาดหัวยังเป็นป้ายชื่อเรื่อง

**5. สิ่งที่เก็บในร่าง (`angles[i].draft`)**

ฟิลด์ `hooks: [{pattern, name, line, headline, score, good, bad, used}]` ฟิลด์ `hook_pattern` และฟิลด์ `hook_score` ไม่ต้องแก้ตาราง

**6. หน้าเว็บ `/marketing`**

- **ช่อง "ประโยคเปิดทางเลือก":** อยู่ใต้แคปชั่นทั้งใน Studio และในการ์ดรอตรวจ (`HookPicker`)
- **ปุ่ม "ใช้ประโยคนี้":** แทนบรรทัดแรกของแคปชั่นพร้อมพาดหัว และพาดหัวนี้ไปถึงโปสเตอร์ด้วย
- **สคริปต์วิดีโอของร่าง AI:** เปิดด้วย hook เดียวกัน (`videoScriptFromDraft`: 0–3 วิ hook, 3–6 วิ บอกว่าคลิปให้อะไร, เนื้อหา, คำกำกับ, ปิด) แทนแม่แบบเดิมที่เปิดด้วย "เรื่องนี้หลายคนยังเข้าใจไม่ตรงกัน" ทุกโพสต์
- **โพสต์เก็บ `hookPattern`:** ไว้เทียบยอดต่อสูตรเมื่อมีตัวเลขโพสต์จริงของเพจเรา

## เลนบทเรียน (ของไวรัล → น้ำหนักสูตร)

**แหล่งข้อมูล** (`server/research/hook-lessons.js`) ใช้ของที่ระบบเก็บอยู่แล้ว ไม่เปิดเบราว์เซอร์และไม่ใช้โควตา Facebook:

| แหล่ง | สิ่งที่ใช้ | วิธีวัด |
|---|---|---|
| RSS ช่อง YouTube ที่เฝ้า | ชื่อคลิป | วิวเทียบค่ากลางของช่อง |
| คลังโพสต์ของตัวเฝ้าเพจ | บรรทัดแรก | ยอดเทียบค่ากลางของเพจ · ต้องมีโพสต์ที่มียอด ≥ 4 โพสต์ |
| คลังแอด Meta | บรรทัดแรก | วันที่ยิงเทียบค่ากลาง · เฉพาะแอดที่พูดถึงบริการแบบเรา |

**วิธีคิด:**
- "แรงกว่าปกติ" คือ ≥ 2 เท่าของค่ากลาง
- lift = สัดส่วนของสูตรในกลุ่มที่แรง ÷ สัดส่วนในตัวอย่างทั้งหมด
- ตัวอย่างซ้ำนับครั้งเดียว และสะสมข้ามสัปดาห์ เพราะ RSS ให้แค่ 15 คลิปล่าสุดต่อช่อง

**ที่เก็บ:**
- อยู่ในเครื่องเท่านั้น (`.local/research/hooks/samples.json` และ `lessons.json`) ข้อความของเพจหรือช่องอื่นไม่ขึ้นรีโป
- ส่งเข้าพรอมต์แค่น้ำหนักสูตร ไม่ส่งข้อความ

**รอบการทำงาน:**
- `npm run research -- run` ทำเองทุก 7 วันก่อนขั้นร่าง และส่งบรรทัดสรุปทางเทเลแกรม
- สั่งเองได้ด้วย `npm run research -- hooks --force`

**รอบแรก (9 พ.ย. 2569):**
- ได้ตัวอย่าง 276 ชิ้น แรงกว่าปกติ 80 ชิ้น
- สูตรของเราส่วนใหญ่ยังมีตัวอย่างไม่ถึง 5 ชิ้น น้ำหนักจึงยังเท่ากัน
- RSS ของบางช่องตอบ 404/500 เป็นช่วง ๆ ระบบข้ามแล้วไปต่อ

## คำสั่งและการทดสอบ

- `npm run test:research` รวมเทสต์ของ `hooks.test.mjs` และ `src/lib/hookOptions.test.mjs`
- `node .local/try-hooks.mjs <id…>` ร่างใหม่ด้วยผู้เขียนจริงโดยไม่บันทึก แล้วพิมพ์เทียบก่อนและหลัง (ไฟล์ในเครื่อง)
- `npm run research -- drafts --no-hooks` ร่างแบบเดิม (ปิดระบบ hook)
- เพิ่มสูตรใหม่:
  1. เพิ่มรายการใน `patterns` ให้ครบทุกฟิลด์
  2. เพิ่มตัวถอดสูตรใน `DETECTORS` ของ `hooks.js`
  3. เทสต์จะตรวจว่าตัวอย่างผ่านกติกาและตัวถอดจับได้

## ยังไม่ได้ทำ / ต่อยอด

- **เทียบยอดต่อสูตรของเพจเราเอง:** ต้องมีตัวเลขโพสต์จริงจากเพจ AssetX ก่อน ตัวเลขชุดนี้คือหลักฐานที่ดีที่สุด เพราะวัดกับคนอ่านของเราโดยตรง
- **สคริปต์วิดีโอเต็มด้วย AI:** ตอนนี้ถอดจากแคปชั่นเท่านั้น
