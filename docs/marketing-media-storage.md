# รูปของหน้า /marketing เก็บเป็นไฟล์แยก

เขียน 23 พ.ย. 2569 · เจ้าของสั่งหลังเจอ "บันทึกขึ้นระบบไม่สำเร็จ" และ "พื้นที่เก็บในเบราว์เซอร์เต็ม"

## ปัญหาเดิม

งานทั้งหมดของหน้า /marketing (ร่าง โพสต์ ไอเดียที่เก็บไว้ และรูปโปสเตอร์) อยู่ในก้อนข้อมูลก้อนเดียว และหน้าเว็บส่งทั้งก้อนขึ้นระบบทุกครั้งที่มีการแก้ รวมถึงทุกครั้งที่หยุดพิมพ์ วันที่ 23 พ.ย. 2569 ก้อนนี้ใหญ่ 5.9 MB โดย 5.3 MB เป็นรูป 8 รูป การบันทึกจึงล้มเป็นบางครั้ง และสำเนาสำรองในเบราว์เซอร์เกินโควตา

## วิธีใหม่

- รูปเก็บเป็นไฟล์ในที่เก็บไฟล์ปิด `marketing-media` (เข้าได้เฉพาะหลังล็อกอิน ผ่าน `/api/marketing-media`) ก้อนข้อมูลเก็บแค่ตำแหน่งของไฟล์
- ในหน้าเว็บ รูปยังอยู่ในหน่วยความจำเหมือนเดิม ทุกส่วนที่แสดงหรือส่งรูป (การ์ดร่าง คลังภาพ การส่ง Facebook) ทำงานแบบเดิม
- ตอนบันทึก รูปที่ย้ายแล้วถูกตัดออกจากก้อน · ตอนเปิดหน้า รูปถูกดึงกลับมาเติม
- รูปใหม่: อัปโหลด → อ่านกลับมาเทียบกับต้นฉบับ → ตรงกันจึงผูกตำแหน่งไฟล์ ขั้นไหนล้ม รูปอยู่ในก้อนตามเดิม ไม่มีทางที่รูปหายเพราะย้ายไม่สำเร็จ
- รูปเดิม 8 รูปย้ายเองครั้งแรกที่เปิดหน้า /marketing หลังขึ้นเว็บ
- ไม่มีอะไรเปลี่ยน = ไม่ส่งก้อนขึ้นระบบซ้ำ

ไม่มีตารางใหม่ ไม่ต้องรัน SQL ไม่ต้องตั้งค่าเพิ่ม (ที่เก็บไฟล์สร้างเองครั้งแรก)

## ไฟล์

| ไฟล์ | หน้าที่ |
|---|---|
| `src/lib/marketingMedia.js` | ตรรกะล้วน: ตัดรูปตอนบันทึก เติมรูปตอนเปิด ผูกตำแหน่งไฟล์ เทียบรูป |
| `server/marketing-media.js` | API: สถานะ อัปโหลด อ่านกลับ (ไม่มีการลบและไม่เขียนทับไฟล์) |
| `src/lib/marketingMediaApi.js` | ตัวเรียก API ฝั่งหน้าเว็บ |
| `src/lib/api.js` | `saveMarketingWorkspace` ตัดรูปที่ย้ายแล้วที่จุดเดียว |
| `src/MarketingPage.jsx` | ลูปย้ายและเติมรูป · สำเนาในเบราว์เซอร์ไม่พกรูป · ไม่ส่งซ้ำเมื่อไม่มีอะไรเปลี่ยน |

ทดสอบ: `npm run test:marketing-proof` (รวม `src/lib/marketingMedia.test.mjs`)

## ปิดใช้ / ย้อนกลับ

- ปิดการย้ายรูปใหม่: ตั้ง `MARKETING_MEDIA_STORAGE=off` บน Vercel แล้ว deploy รูปใหม่จะอยู่ในก้อนเหมือนเดิม
- รูปที่ย้ายไปแล้วยังต้องอ่านจากที่เก็บไฟล์ การปิดสวิตช์จึงไม่ดึงรูปเหล่านั้นกลับเข้าก้อน ถ้าต้องย้อนทั้งหมดให้กู้จากไฟล์สำรอง
- ไฟล์สำรองก่อนย้าย (ทั้งก้อน รวมรูป 8 รูป) อยู่บนคอมสำนักงานที่ `.local/backups/` ไม่ขึ้น git · ตรวจหลังย้ายด้วย `node .local/backups/verify-media.mjs`

## ข้อจำกัด

- รูปใหญ่เกิน 3 MB ไม่ย้าย อยู่ในก้อนต่อไป (เพดานขนาดคำขอของเซิร์ฟเวอร์)
- ลบรูปในหน้าเว็บ = เอาออกจากก้อน ไฟล์ในที่เก็บยังอยู่ ยังไม่มีตัวเก็บกวาด
- เปิดหน้าครั้งแรกต้องดึงรูปทีละรูป รูปบนการ์ดจึงขึ้นช้ากว่าข้อความเล็กน้อย ระหว่างนั้นกดส่ง Facebook ของโพสต์ที่รูปยังไม่มา ระบบจะให้รอ
- แท็บเก่าที่เปิดค้างไว้ก่อนขึ้นเว็บไม่รู้จักตำแหน่งไฟล์ จะไม่เห็นรูปที่ย้ายแล้ว ต้องรีเฟรชทุกแท็บหลังขึ้นเว็บ
- ส่วนอื่นของก้อน (ร่าง โพสต์) ยังเป็นแบบเครื่องล่าสุดเขียนทับ เหมือนเดิม
