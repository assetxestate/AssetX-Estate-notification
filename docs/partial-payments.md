# ชำระไม่ครบ / ชำระเพิ่ม (งวดดอกเบี้ย)

ใช้เมื่อลูกค้าจ่ายงวดดอกเบี้ยไม่ครบ แล้วมาจ่ายส่วนที่เหลือทีหลัง ใช้ได้ทั้งงวดของสัญญาหลักและงวดของวงเงินเพิ่ม

## ติดตั้ง (ครั้งเดียว)

1. รัน `supabase_payment_additions.sql` ใน SQL Editor ของโปรเจกต์ AssetX ใน Supabase ไฟล์นี้รันซ้ำได้
   - ต้องมีตาราง `customers`, `payment_records`, `contract_topups` (id แบบ uuid) และ `topup_payment_records` อยู่ก่อน ฐานข้อมูลจริงมีครบแล้ว
   - ทดลองรันไฟล์นี้บน Postgres จำลอง (PGlite) แล้ว: รันซ้ำได้ ตัวกันการลบและสิทธิ์ทำงานตามที่เขียนไว้
2. เซิร์ฟเวอร์ต้องมี `SUPABASE_SERVICE_ROLE_KEY` ซึ่งตั้งบน Vercel ไว้แล้ว เพราะหน้า /diary และ Notice ใช้คีย์เดียวกัน ห้ามตั้งชื่อคีย์นี้ขึ้นต้นด้วย `VITE_`
3. ระหว่างที่ยังไม่ได้รัน SQL:
   - หน้าเว็บยังบอกได้ว่างวดไหนจ่ายไม่ครบ แต่ปุ่ม "＋ ชำระเพิ่ม" กับ "ยกเว้นส่วนที่ขาด" จะกดไม่ได้ และมีข้อความบอกให้รันไฟล์
   - ทั้งงานเตือน LINE ตอนเช้าและปุ่ม LINE/คัดลอกในหน้าเว็บ ยังเตือนงวดอื่นตามปกติ แต่ยังไม่ทวงส่วนที่ขาด (ขึ้นว่า "ยังทวงส่วนที่ขาดไม่ได้") เพราะถ้าลูกค้ามาจ่ายส่วนที่เหลือ ระบบยังบันทึกไม่ได้ จะกลายเป็นทวงเงินที่รับแล้วซ้ำ
   - ควรรัน SQL ก่อนหรือพร้อมกับวันที่ขึ้นเว็บ

## วิธีใช้

- **บันทึกครั้งแรก** ทำเหมือนเดิมด้วยปุ่ม 💳 บันทึก แล้วใส่ยอดที่ได้รับจริง ถ้ายอดน้อยกว่ายอดงวด ระบบจะแสดงว่าชำระไม่ครบ:
  - งวดนั้นขึ้นกล่องสีเหลือง "⚠️ ชำระไม่ครบ · ขาด X บาท"
  - แท็บ 💳 การชำระ มีการ์ด "ชำระไม่ครบ" ที่รวมทุกงวดที่ยังขาด ทั้งสัญญาหลักและวงเงินเพิ่ม
- **นัดวันชำระส่วนที่ขาด** ใช้ปุ่ม 📅 เลื่อนนัด / นัดวันชำระ ของงวดนั้น:
  - วันครบกำหนดของงวดจะย้ายไปวันที่นัด ส่วนวันเดิมยังเก็บไว้ในช่อง "เลื่อนจาก"
  - หน้าต่างเลื่อนนัดจะบอกว่าจ่ายแล้วเท่าไร และยังขาดเท่าไร
  - นัดทันทีที่ตกลงกับลูกค้า ถ้ายังไม่นัด งานเตือนตอนเช้า (08:00) จะทวงส่วนที่ขาดตามวันครบกำหนดเดิม ทั้งรอบล่วงหน้า 7 วันและรอบวันครบกำหนด
- **ลูกค้ามาจ่ายส่วนที่เหลือ** กด "＋ ชำระเพิ่ม":
  - ยอดตั้งต้นในหน้าต่างคือยอดที่ยังขาด แนบสลิปได้
  - รายการนี้เป็นรายการใหม่ ไม่ทับบันทึกครั้งแรก
  - ถ้ายอดรวมยังไม่ครบ กดชำระเพิ่มได้อีก
- **ไม่เก็บส่วนที่เหลือแล้ว** เช่น ให้ส่วนลด ให้กด "ยกเว้นส่วนที่ขาด" แล้วใส่เหตุผล งวดนั้นจะจบ ยอดที่ยกเว้นไม่นับเป็นเงินที่รับจริง
- **บันทึกผิด** กด "ยกเลิกรายการ" ที่รายการชำระเพิ่มหรือยกเว้นนั้น แล้วใส่เหตุผล:
  - รายการยังอยู่ในประวัติ แสดงเป็นขีดฆ่าพร้อมเหตุผล
  - งวดจะกลับไปเป็นค้างตามยอดจริง
- **บันทึกครั้งแรกของงวดที่มีรายการชำระเพิ่มแล้ว** ลบไม่ได้ ต้องยกเลิกรายการชำระเพิ่มของงวดนั้นก่อน หน้าต่างแก้บันทึกครั้งแรกจะเตือนว่า อย่าแก้ยอดเพื่อบันทึกเงินที่มาจ่ายเพิ่ม
- **ปิดสัญญา** ถ้ายังมีงวดที่ชำระไม่ครบ หน้าต่างยืนยันจะบอกจำนวนงวดและยอดที่ขาดรวมก่อน

## การเตือน

- **งานเตือน LINE ตอนเช้า** (`api/daily-notify.js`):
  - เตือนงวดที่ชำระไม่ครบล่วงหน้า 7 วัน และในวันนัด โดยใช้ยอดที่ยังขาด
  - ข้อความมีบรรทัด "ชำระแล้ว X บาท จากยอด Y บาท" ถ้ามีการยกเว้นบางส่วนจะบอกยอดที่ยกเว้นด้วย
  - ถ้ามีหลายรายการครบวันเดียวกัน ข้อความรวมจะแสดงทุกรายการ ทั้งงวดสัญญาหลักหลายงวดและงวดวงเงินเพิ่ม
- **เมื่อจ่ายครบหรือยกเว้นแล้ว** ระบบหยุดเตือนงวดนั้น ถ้ายกเลิกรายการชำระเพิ่ม งวดจะกลับมาค้างและเตือนอีกครั้ง
- **อ่านรายการชำระเพิ่มไม่ได้** เช่น ไม่มีคีย์ หรือฐานข้อมูลมีปัญหา:
  - งานเตือนจะไม่ทวงงวดที่จ่ายไม่ครบ เพราะลูกค้าอาจจ่ายส่วนที่เหลือไปแล้ว งวดอื่นยังเตือนตามปกติ
  - ผลลัพธ์ของงานมีช่อง `warnings` บอกสาเหตุ
- **ปุ่ม ส่ง LINE / คัดลอกข้อความในหน้าเว็บ** ใช้ยอดและการรวมรายการแบบเดียวกับงานเตือนตอนเช้า:
  - ข้อความเดียวต่อ "ลูกค้า + วันครบกำหนด" ปุ่มส่ง LINE อยู่ที่งวดแรกของวันนั้น
  - งวดอื่นที่ครบวันเดียวกันขึ้นว่า "รวมส่งกับงวด X" เพื่อไม่ให้ทวงวงเงินเพิ่มซ้ำสองข้อความ
- **หน้าเว็บโหลดรายการชำระเพิ่มไม่สำเร็จ** เช่น เน็ตหลุด หรือเซสชันหมดอายุ:
  - แท็บการชำระมีแถบเตือนพร้อมปุ่มลองใหม่ หน้า Dashboard ก็มีแถบเตือนว่ายอดรับชำระและค้างชำระอาจยังไม่ครบ
  - ยอดปิดรีไฟแนนซ์มีหมายเหตุเตือน และหน้าต่างยืนยันปิดสัญญาก็เตือนด้วย
  - งวดที่บันทึกครั้งแรกไม่ครบจะยังไม่ขึ้นว่าขาด และไม่มีปุ่มทวง เพราะยังไม่รู้ว่าลูกค้าจ่ายเพิ่มแล้วหรือยัง
  - ลบบันทึกครั้งแรกไม่ได้จนกว่าจะตรวจกับเซิร์ฟเวอร์ได้
- **ผู้ช่วยเทเลแกรม** ได้รับรายการงวดที่ชำระไม่ครบซึ่งคิดยอดไว้แล้ว ส่งแค่ตัวเลขกับวันที่ ไม่ส่งหมายเหตุ

## ข้อมูล

| ตาราง | เก็บอะไร |
|---|---|
| `payment_records` / `topup_payment_records` | บันทึกครั้งแรกของงวด งวดละรายการ (เหมือนเดิม) |
| `payment_additions` | ชำระเพิ่มและยกเว้นส่วนที่ขาด เพิ่มได้อย่างเดียว ยกเลิกด้วย `voided_at` และไม่มีสิทธิ์ลบ |

- งวด "ครบ" เมื่อบันทึกครั้งแรก + ชำระเพิ่ม + ยกเว้น ≥ ยอดของงวด ไม่นับรายการที่ยกเลิก
- ยอดของงวดมาจาก:
  - สัญญาหลัก: `customers.amount`
  - วงเงินเพิ่ม: `contract_topups.interest_amount`
- งวดหักดอกล่วงหน้าวันทำสัญญา (`ADVANCE_DEDUCTION`) ถือว่าครบ
- คิดเงินเป็นสตางค์ (จำนวนเต็ม) และไม่รับจำนวนเงินที่มีทศนิยมเกิน 2 ตำแหน่ง
- เบราว์เซอร์อ่านหรือเขียน `payment_additions` ตรงไม่ได้ ต้องผ่าน `/api/payment-additions` ซึ่งตรวจการล็อกอิน และใช้ service role ที่เซิร์ฟเวอร์
- **กันบันทึกซ้ำ:**
  - แต่ละรายการมีลำดับต่องวด (`seq`) ที่ฐานข้อมูลห้ามซ้ำ ถ้าสองคนกดบันทึกงวดเดียวกันพร้อมกัน จะผ่านได้รายการเดียว อีกรายการได้ข้อความให้โหลดใหม่
  - หน้าต่างชำระเพิ่มส่งรหัสรายการของตัวเอง ถ้ากดซ้ำหรือลองใหม่หลังเน็ตหลุด จะไม่เกิดรายการซ้ำ
  - ถ้าครั้งแรกบันทึกไปแล้วแต่คำตอบหายระหว่างทาง การลองใหม่จะได้รายการเดิมกลับมาว่า "บันทึกแล้ว" แม้งวดจะครบไปแล้ว
  - ถ้าลองใหม่ด้วยยอดที่แก้แล้ว ระบบจะบอกยอดที่บันทึกไว้ครั้งแรก ให้ยกเลิกรายการนั้นแล้วบันทึกใหม่ ระบบไม่แก้ทับให้เอง
  - เปิดหน้าต่างใหม่ของงวดเดิมหลังเน็ตหลุด ระบบใช้รหัสเดิม จึงไม่บันทึกซ้ำ
- **ฐานข้อมูลกันประวัติขาดตอนเอง:**
  - ลบบันทึกครั้งแรกของงวดที่ยังมีรายการชำระเพิ่มหรือยกเว้นไม่ได้ กันได้แม้กดจากหน้าเว็บรุ่นเก่า หรือสองเครื่องกดพร้อมกัน
  - ลบวงเงินเพิ่มหรือลูกค้าที่มีประวัติชำระเพิ่มไม่ได้
  - เพิ่มรายการชำระเพิ่มได้เฉพาะงวดที่มีบันทึกครั้งแรก
- **หน้าต่างบันทึก** รอผลจากฐานข้อมูลก่อนปิด ถ้าบันทึกไม่สำเร็จ หน้าต่างยังเปิดอยู่ และข้อมูลที่กรอกกับสลิปไม่หาย

## ข้อจำกัดที่รู้แล้ว

- **ยอดของงวดไม่มีสำเนาแยกรายงวด** ถ้าเพิ่มดอกเบี้ย/งวดในหน้าแก้ข้อมูลลูกค้า งวดเก่าที่จ่ายด้วยยอดเดิมจะขึ้นว่าชำระไม่ครบ หน้าแก้ไขจะเตือนก่อนบันทึก
- **การนัดวันชำระใช้ระบบเลื่อนนัดเดิม** ถ้าเลื่อนหลายครั้ง:
  - ช่อง "เลื่อนจาก" เก็บแค่วันครบกำหนดแรกสุด
  - บันทึกการเลื่อนใช้ข้อความล่าสุด
- **ส่วนที่ขาดซึ่งเลยวันนัดแล้ว** ไม่มีข้อความ LINE ทวงอัตโนมัติ เหมือนงวดค้างทั่วไป แต่ยังขึ้นในการ์ด "ชำระไม่ครบ" และรายการค้างชำระ
- **โอนครั้งเดียวที่จ่ายหลายรายการ** (เช่น สัญญาหลัก + วงเงินเพิ่ม) ยังต้องแยกบันทึกทีละงวดเอง
- **Dashboard นับวันค้างของงวดที่เลื่อนจากวันครบกำหนดเดิม** (เป็นแบบนี้อยู่แล้วก่อนเพิ่มระบบนี้) ส่วนแท็บการชำระนับจากวันที่นัดใหม่
