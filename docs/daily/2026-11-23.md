# สรุปประจำวัน · 23 พ.ย. 2026

> เจ้าของส่งบรีฟให้ยกระดับหน้าการตลาดจาก "ค้นหัวข้อแล้วให้ระบบเขียน" เป็นระบบที่โพสต์ทุกชิ้นตามกลับไปหาหลักฐานได้ วันนี้ทำเฟสแรกเสร็จและเปิดใช้บนเว็บจริง: สร้างโพสต์จากข้อมูลหน้างานและข้ออ้างที่ตรวจแล้ว และการอนุมัติของคนถูกบันทึกและตรวจซ้ำที่เซิร์ฟเวอร์ก่อนส่งออก

## ภาพรวม

- ต้น session: ไดอารี่ไม่มีคำสั่งใหม่และไม่มีทางที่เจ้าของเลือกค้าง
- บรีฟแบ่งงานเป็น 4 เฟส วันนี้ทำเฟสแรก (ความน่าเชื่อถือและหลักฐาน) เฟสที่เหลือยังไม่เริ่ม

## งานที่ทำ

### 1. สร้างโพสต์จากข้อมูลจริง และ Proof Card

- **เปลี่ยนอะไร:** หน้าเขียนโพสต์ใหม่มีแผง "สร้างจากข้อมูลจริง": บรีฟ บันทึกหน้างาน แหล่งข้อมูล และข้ออ้างสำคัญของโพสต์ ผูกข้ออ้างกับแหล่งแล้วคนกดยืนยัน จากนั้นระบบเรียงร่างจากข้อมูลที่กรอกและข้ออ้างที่ยืนยันแล้วเท่านั้น · ช่องพิมพ์หัวข้อแบบเดิมยังอยู่สำหรับโพสต์ความรู้ทั่วไป
- **ทำไม:** โพสต์ที่ต่างจากเพจอื่นต้องมาจากข้อมูลและวิธีคิดของเราเอง และต้องไม่มีข้อเท็จจริงที่ระบบแต่งขึ้น · ร่างแบบนี้ไม่ใช้ AI จึงไม่มีทางเติมตัวเลขหรือเคสให้เอง
- **ผล:** ข้ออ้างแยก 7 ประเภท ราคาเสนอขายกับราคาซื้อขายจริงไม่ปนกัน ตัวอย่างสมมติต้องติดป้าย · ข้ออ้างที่ยังไม่ยืนยันไม่ถูกเขียนลงร่าง · ข้อมูลเก็บในตารางแยก สองแท็บแก้พร้อมกันได้ข้อความแจ้งแทนการเขียนทับ · บรีฟรูปของร่างแบบนี้ยังมาจากแม่แบบหัวข้อ
- commit `8c537c5`

### 2. ด่านตรวจแยกหมวด และการอนุมัติที่เซิร์ฟเวอร์บันทึก

- **เปลี่ยนอะไร:** การ์ดร่างมีปุ่ม "ตรวจหลักฐาน" แสดงตัวบล็อกแยกสามหมวด (ถ้อยคำและกฎหมาย หลักฐาน ข้อมูลส่วนบุคคล) กับข้อสังเกตที่ไม่บล็อก · กดอนุมัติแล้วเซิร์ฟเวอร์ตรวจเองและเก็บชื่อผู้ตรวจ เวลา และลายนิ้วมือของเนื้อหา · ตอนส่ง Facebook เซิร์ฟเวอร์เทียบกับบันทึกนี้ซ้ำ
- **ทำไม:** ระหว่างตรวจโค้ดพบว่าด่านส่งออกเดิมเชื่อสถานะ "ผ่านการตรวจ" ที่หน้าเว็บส่งมา จึงข้ามการอนุมัติได้ถ้าเรียกตรง · บรีฟไม่ได้ระบุข้อนี้
- **ผล:** แก้ข้อความ ภาพ หรือข้ออ้างหลังอนุมัติ ส่งออกไม่ได้จนกว่าจะอนุมัติใหม่ · หลักฐานหมดอายุหลังอนุมัติก็ส่งไม่ได้ · ระบบไม่ตัดสินเพดานดอกเบี้ยเอง โพสต์ที่มีตัวเลขอัตราต้องให้คนเทียบกับตัวบทเป็นรายกรณี · ผู้ตรวจเป็นชื่อที่พิมพ์เอง เพราะแอปมีบัญชีเดียว · เทสต์ใหม่ 28 ข้อผ่าน ชุดเดิมของหน้าการตลาดผ่านครบ ตรวจหน้าจอด้วยเบราว์เซอร์กับฐานข้อมูลจำลองผ่าน 21 ข้อ
- commit `8c537c5`

### 3. เปิดใช้บนเว็บจริง

- **เปลี่ยนอะไร:** เจ้าของรันไฟล์ SQL และตั้งค่าเปิดใช้บน Vercel แล้วสั่งให้ขึ้นเว็บ · แผงใหม่ขึ้นบนหน้าเว็บจริงแล้ว
- **ทำไม:** เจ้าของเลือกเปิดใช้ทันทีหลังเฟสแรกเสร็จ
- **ผล:** ตารางใหม่ครบ 5 ตาราง และคีย์ฝั่งเบราว์เซอร์อ่านไม่ได้ · ระหว่างเปิดใช้ เว็บย้อนกลับไปโค้ดชุดเก่าหนึ่งครั้ง เพราะปุ่ม Redeploy ถูกกดที่รายการเก่า แก้ด้วยการส่ง commit เปล่าให้ระบบสร้างใหม่จากโค้ดล่าสุด · ยังไม่มีการทำครบหนึ่งรอบด้วยข้อมูลจริงบนเว็บจริง
