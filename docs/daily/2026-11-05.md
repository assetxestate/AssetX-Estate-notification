## งานที่ทำ

### 1. ตรวจไฟล์ SQL ชำระเพิ่มบนฐานข้อมูลจริง

- **ผลที่ได้:** ตาราง `payment_additions` มีครบทุกคอลัมน์และยังว่าง · ผู้ใช้ที่ไม่ได้ล็อกอินอ่านและเขียนไม่ได้ · เซิร์ฟเวอร์เพิ่มและแก้รายการได้แต่ลบไม่ได้ · ตัวตรวจ "ต้องมีบันทึกแรกของงวดก่อน" ทำงานทั้งงวดสัญญาหลักและงวดวงเงินเพิ่ม
- **วิธีตรวจ:** ส่งรายการทดสอบที่บันทึกไม่ได้แน่นอน (ลูกค้าที่ไม่มีอยู่จริงและยอด 0 บาท ซึ่งผิดเงื่อนไขทั้งสองข้อ) แล้วดูว่าฐานข้อมูลปฏิเสธด้วยเหตุผลที่ถูก — ตารางนี้ห้ามลบ ถ้ารายการทดสอบหลุดเข้าไปจะลบทิ้งไม่ได้
- **ผล:** ผ่าน 9/9 · ไม่มีรายการทดสอบค้างในตาราง

### 2. ลองเว็บรุ่นใหม่กับข้อมูลจริงก่อนขึ้นเว็บ

- **ผลที่ได้:** เปิดเว็บรุ่นใหม่ในเครื่อง ต่อฐานข้อมูลจริง และบล็อกการเขียนทุกชนิด: ระบบชำระเพิ่มพร้อมใช้ ไม่มีแถบ "รอรันไฟล์ SQL" · การ์ด "⚠️ ชำระไม่ครบ" แสดงงวดจริงที่ขาดถูกต้อง · หน้าต่างนัดวันชำระและหน้าต่างชำระเพิ่มเปิดได้ ตัวเลขถูก (ปิดโดยไม่บันทึก) · งานเตือนตอนเช้าอ่านตารางจริงได้ทุกวันใน 27 วันที่จำลอง · build ผ่าน · เทสต์ 15 ชุดผ่าน · จำนวนฟังก์ชันบน Vercel เท่าเดิม และไม่ต้องตั้งค่าเพิ่ม
- **ทำไม:** โค้ดเขียนเสร็จก่อนมีตารางจริง จึงต้องดูว่าทำงานกับข้อมูลจริงก่อนขึ้นเว็บ
- **ยังไม่ได้ลองจริง:** การบันทึก "＋ ชำระเพิ่ม" และการยกเลิกรายการบนฐานข้อมูลจริง เพราะรายการที่ลองจะลบไม่ได้ — ครั้งแรกที่เจ้าของกดคือการใช้จริงครั้งแรก · ถ้าบันทึกไม่สำเร็จ หน้าต่างจะเปิดค้างพร้อมแจ้งข้อผิดพลาด ข้อมูลที่กรอกไม่หาย

### 3. แก้เส้นตายเลื่อนนัดงวดที่ลูกค้าขอจ่ายส่วนที่เหลือ

- **เปลี่ยนอะไร:** ข้อค้างในไดอารี่ 4 พ.ย. บอกเส้นตายใหม่: เลื่อนนัดให้เสร็จก่อนรอบเตือน 08:00 ของวันครบกำหนดเดิมของงวดนั้น (เดิมเขียนว่าก่อนรอบเตือนล่วงหน้า 7 วันของวันนัด) · `docs/partial-payments.md` เพิ่มว่าให้นัดวันชำระส่วนที่ขาดทันทีที่ตกลงกับลูกค้า
- **ทำไม:** จำลองฉากที่เจ้าของยังไม่ได้ทำอะไร (รอบ 4 พ.ย. ไม่มีฉากนี้ เพราะทุกฉากเลื่อนนัดไว้ก่อน) แล้วพบว่าวันครบกำหนดเดิมของงวดนั้นจะเข้ารอบเตือน "ครบกำหนดวันนี้" ก่อน ถ้าเว็บรุ่นใหม่ขึ้นแล้วยังไม่เลื่อน เช้าวันนั้นระบบจะส่ง LINE ทวงส่วนที่ขาด · หน้าเว็บรุ่นเดิมเลื่อนงวดวงเงินเพิ่มที่มีบันทึกแล้วไม่ได้ จึงเลื่อนได้หลังขึ้นเว็บเท่านั้น
- **commit:** 485f4d6

### 4. push ขึ้นเว็บ

- **เปลี่ยนอะไร:** เจ้าของพิมพ์ "push" → ส่ง 4 commit ที่ค้างขึ้นพร้อมกัน: ระบบชำระไม่ครบ/ชำระเพิ่ม (2fe054d) · ไดอารี่ 4 พ.ย. 2 ตัว · ผลตรวจ SQL และเส้นตายที่แก้ (485f4d6) · ก่อน push รันเทสต์ชุดการชำระอีกรอบ ผ่าน 63/63
- **ทำไม:** ตรวจกับฐานข้อมูลจริงครบแล้ว และ push ก่อนรอบเตือนตอนเช้าของวันครบกำหนดเดิม ยังมีเวลาเลื่อนนัดให้ทัน
- **ผล:** push 11:33 น. · เว็บรุ่นใหม่ขึ้นแล้วราว 11:34 น. — ตรวจจากเว็บจริง: เส้นทาง `/api/payment-additions` ตอบแบบระบบใหม่ (ต้องล็อกอินก่อน) · Vercel แจ้ง build สำเร็จ · ไฟล์หน้าเว็บมีโค้ดชำระเพิ่มแล้ว · ส่วนที่ต้องล็อกอิน (โหลดรายการจริงบนเว็บจริง) ยังไม่ได้ตรวจ จะเห็นตอนเจ้าของเปิดแท็บการชำระ
- **ต่อไป:** เจ้าของเลื่อนนัดงวดนั้นไปวันที่ลูกค้านัด ที่การ์ด "⚠️ ชำระไม่ครบ" → ปุ่ม "📅 นัดวันชำระ" (ช่องวันที่ตั้งต้นเป็นวันครบกำหนดเดิม ต้องเปลี่ยนเป็นวันนัด) ให้เสร็จก่อน 08:00 ของวันครบกำหนดเดิม — เลื่อนแล้วตอนบ่าย (เรื่องที่ 5)

### 5. ตรวจหลังเจ้าของเลื่อนนัด

- **ผลที่ได้:** เจ้าของเลื่อนนัดงวดวงเงินเพิ่มที่ลูกค้าขอจ่ายส่วนที่เหลือไปวันที่ลูกค้านัดแล้วตอนบ่าย (บนเว็บจริง) · อ่านฐานข้อมูลแบบอ่านอย่างเดียว: วันนัดใหม่บันทึกถูก ยังเก็บวันนัดเดิมไว้ และยังไม่มีรายการชำระเพิ่มในตาราง
- **ทำไม:** ถ้าวันนัดใหม่บันทึกไม่ถูก รอบเตือน 08:00 ของวันครบกำหนดเดิมจะส่ง LINE ทวงส่วนที่ขาด
- **ผล:** จำลองรอบเตือนตอนเช้าบนข้อมูลจริงโดยไม่ส่งจริง: เช้าวันครบกำหนดเดิมไม่มีข้อความถึงลูกค้ารายนี้ · ระบบจะเตือนส่วนที่ขาดล่วงหน้า 7 วันและในวันนัดใหม่ โดยบอกยอดที่ยังขาดและยอดที่ชำระแล้ว · ยังไม่ได้ลอง: การกด "＋ ชำระเพิ่ม" ครั้งแรก (รอลูกค้าโอนตามนัด)
