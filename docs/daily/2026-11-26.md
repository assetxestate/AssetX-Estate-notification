# สรุปประจำวัน · 26 พ.ย. 2026

> ตรวจงานค้างในไดอารี่แล้วปิดข้อที่เสร็จหรือถูกแทนที่ไปแล้ว 14 ข้อ จากนั้นทำข้อค้างของ Claude หนึ่งข้อ: Reel ต้องผ่านการตรวจหลักฐานและมีบันทึกการอนุมัติของคนก่อนเผยแพร่ แบบเดียวกับโพสต์

## งานที่ทำ

### 1. ปิดข้อค้างในไดอารี่ที่จบไปแล้ว

- **เปลี่ยนอะไร:** ไล่ข้อค้างทั้งหมดเทียบกับโค้ดและบันทึกของวันถัด ๆ มา แล้วปิด 14 ข้อที่งานเสร็จแล้วหรือถูกงานรุ่นใหม่แทนที่
- **ทำไม:** รายการค้างยาวจนข้อที่ยังต้องทำจริงจมอยู่ในข้อที่จบไปแล้ว
- **ผล:** เหลือข้อค้าง 67 ข้อ · การปิดสองข้อของต้นเดือนทำให้เวลาที่ปิดเดิมถูกแทนด้วยเวลาของวันนี้

### 2. บันทึกการอนุมัติของ Reel

- **เปลี่ยนอะไร:** ในหน้าทำวิดีโอ ก่อนเผยแพร่ Reel ต้องกดตรวจหลักฐาน ใส่ชื่อผู้ตรวจ ติ๊กว่าดูคลิปจนจบแล้ว และกดอนุมัติ · Reel มีบันทึกการอนุมัติของตัวเองแยกจากของโพสต์ · การอนุมัติผูกกับข้อความใต้คลิป ไฟล์คลิป และข้ออ้างของโพสต์ · เซิร์ฟเวอร์ตรวจบันทึกซ้ำทั้งก่อนส่งไฟล์ให้ Facebook และก่อนเผยแพร่
- **ทำไม:** เดิมข้อความใต้คลิปผ่านแค่ด่านคำของแบรนด์กับการกดยืนยัน แก้ข้อความในแผงแล้วไม่มีอะไรเทียบกับฉบับที่อนุมัติ หน้าจอจึงต้องเตือนไว้
- **ผล:** แก้ข้อความหรือเปลี่ยนคลิปหลังอนุมัติต้องอนุมัติใหม่ และเรียก API ตรงก็ข้ามไม่ได้ · ใช้ตารางเดิม ไม่ต้องรัน SQL · ปิดธงตรวจหลักฐานแล้วระบบกลับไปใช้ด่านเดิมพร้อมคำเตือนเดิม · ทดสอบอัตโนมัติผ่านครบ และตรวจหน้าจอด้วยฐานข้อมูลกับ Facebook จำลองผ่านทั้งสองโหมด
- **ข้อจำกัด:** ด่านอ่านได้แค่ข้อความใต้คลิป ไม่ได้อ่านเสียงหรือตัวหนังสือในคลิป จึงบังคับให้ผู้ตรวจยืนยันว่าดูคลิปแล้ว · บทพูดใน storyboard ยังไม่อยู่ในด่านนี้ · ยังไม่ได้ลองกับ Reel จริงบนเว็บ
