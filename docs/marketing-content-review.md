# การร่างและตรวจคอนเทนต์ AssetX

## สิ่งที่แก้

- ส่งหัวข้อจาก Studio ถึงตัวร่างจริง และเก็บหัวข้อต้นทางกับโพสต์
- แยกแม่แบบซื้อทรัพย์ ขายทรัพย์ ขายฝาก จำนอง เปรียบเทียบสัญญา และสภาพคล่อง
- ใช้หมวดเดียวกันสำหรับแคปชั่น ภาพ สคริปต์ และแฮชแท็ก ไม่หยิบข้อเสนอขายฝากของแบรนด์มาแทนหัวข้อซื้อที่ดิน
- ไม่ตรวจข้อความคำสั่งใน campaignContext ราวกับเป็นข้อความโฆษณาที่จะเผยแพร่
- แยกผลตรวจเนื้อหาออกจากสถานะอนุมัติ ตรวจซ้ำเมื่อกดอนุมัติและก่อนส่ง Facebook ฝั่งเซิร์ฟเวอร์
- การแก้แคปชั่นหรือช่องทางทำให้ต้องอนุมัติใหม่
- คะแนนโครงสร้างไม่ใช่คะแนนความถูกต้องของข้อเท็จจริง

## วิธีตรวจงาน

1. สร้างโพสต์หัวข้อ `ข้อควรรู้ก่อนซื้อที่ดินเปล่า ทั้งทำเลทอง`
2. ตรวจว่ารายการเป็นเอกสารสิทธิ์ ทำเล/ทางเข้าออก และราคา/ค่าใช้จ่าย ไม่มียอดสินไถ่
3. ส่งรออนุมัติ ผลตรวจเบื้องต้นผ่านได้ แต่สถานะต้องยังเป็นรอตรวจ
4. หากเติมข้อความรับประกันอนุมัติ หรือเติมสินไถ่ในเรื่องซื้อที่ดิน ต้องกดอนุมัติไม่ผ่าน
5. แก้ข้อความแล้วตรวจอีกครั้ง การส่ง Facebook ยังต้องได้รับอนุมัติจากคน

## ข้อจำกัด

ระบบนี้ยังเป็นแม่แบบและกฎตรวจข้อความ ไม่ใช่เครื่องตรวจข้อเท็จจริงหรือที่ปรึกษากฎหมาย
หัวข้อที่ไม่รู้จักจะให้ร่างแจ้งข้อมูลไม่เพียงพอและไม่อนุญาตให้เผยแพร่ผ่านขั้นตอนนี้
ข้อความหัวข้อจากผู้ใช้ยังต้องตรวจข้อกล่าวอ้างด้วยคน แม้คะแนนโครงสร้างสูง
ต้องตรวจเอกสาร แหล่งอ้างอิง ตัวเลข สิทธิใช้รูป และความยินยอมสำหรับเคสจริงก่อนอนุมัติ
ไม่มีการค้นข้อมูลกฎหมายหรือข่าวล่าสุดอัตโนมัติ และไม่มีการเรียก AI ที่มีค่าใช้จ่ายในตัวร่างนี้
ร่างเก่าไม่ถูกเขียนทับอัตโนมัติ ควรสร้างร่างใหม่จากหัวข้อต้นทางเมื่อพบข้อความปนเรื่อง
การทดสอบใช้ข้อมูลจำลอง ไม่แก้ฐานข้อมูล Production และไม่เผยแพร่ Facebook จริง

## เลขคอนเทนต์ (#12)

คอนเทนต์ทุกชิ้นในหน้า `/marketing` มีเลขกำกับ เพื่อให้เจ้าของ ทีม และ Claude อ้างถึงชิ้นเดียวกันได้ตรงตัวเวลาสั่งแก้

- ได้เลขครั้งเดียวตอนคอนเทนต์เข้าระบบ ทั้งร่างจากไอเดีย ร่างจาก Studio ร่างจากผู้ช่วย Telegram และร่างตัวอย่างที่ถูกแก้ครั้งแรก
- เลขไม่เปลี่ยนเมื่อแก้ข้อความ อนุมัติ ตั้งเวลา พักไว้ หรือกู้คืน และไม่ถูกใช้ซ้ำแม้คอนเทนต์ถูกลบ
- คอนเทนต์เก่าที่มีอยู่ก่อนวันที่ 4 พ.ย. 2569 ได้เลขเรียงจากชิ้นที่เก่าที่สุดเป็น #1 ตอนเปิดหน้าครั้งแรกหลังอัปเดต ทุกเครื่องได้เลขชุดเดียวกัน
- ร่างตัวอย่างจากแม่แบบยังไม่มีเลข เพราะยังไม่ใช่คอนเทนต์ของเรา
- เลขเก็บแยกจากแคปชั่น จึงไม่ไปโผล่ในโพสต์จริงบน Facebook หรือ LINE และไม่อยู่ในช่องตัวอย่างช่องทางของคลังผลงาน
- ร่างที่สร้างระหว่างหน้ากำลังโหลดข้อมูลจากระบบจะได้เลขเมื่อโหลดเสร็จ (ป้ายเลขขึ้นหลังจากนั้น)
- ระหว่างหน้ากำลังโหลดข้อมูลจากระบบ การแก้ข้อความ อนุมัติ ตั้งเวลา พักไว้ ลบ โพสต์ หรือออกแบบภาพให้คอนเทนต์ที่มีอยู่แล้วต้องรอให้โหลดเสร็จก่อน (มีแถบบอกบนรายการ และช่องแคปชั่นแก้ไม่ได้ชั่วคราว) เพราะหน้าจอยังแสดงสำเนาในเครื่องที่อาจเก่ากว่าข้อมูลในระบบ ส่วนการสร้างร่างใหม่ทำได้ตามปกติ
- หน้าต่างออกแบบภาพที่เปิดค้างไว้ จะแนบภาพได้เฉพาะเมื่อคอนเทนต์ยังเป็นร่างอยู่ตอนกดบันทึก (ถ้าระหว่างนั้นถูกลบ อนุมัติ หรือโพสต์ไปแล้ว จะมีข้อความบอกในหน้าต่าง)
- ลิงก์ร่างจาก Telegram ใช้ครั้งเดียว: นำเข้าแล้วลิงก์หายจากแถบที่อยู่ · อ่านหรือบันทึกร่างไม่สำเร็จเพราะเครือข่าย ลิงก์ยังอยู่ให้รีเฟรชลองใหม่เมื่อแถบด้านบนขึ้น "บันทึกแล้ว" (เลขที่แจกไปแล้วถูกข้าม ไม่ใช้ซ้ำ) · ร่างที่ลบแล้วเปิดลิงก์เดิมจะมีข้อความบอกว่าไม่นำเข้าซ้ำ

เลขแสดงบนการ์ดในแท็บ ร่าง และ โพสต์ ในปฏิทิน คลังผลงาน ห้องภาพ และหน้าต่างออกแบบภาพ
กดป้ายเลขบนการ์ดเพื่อคัดลอกข้อความ เช่น "คอนเทนต์ #12 · หัวข้อ" ไปวางในแชต
ช่อง "ไปที่ #เลข" ข้างเมนูเครื่องมือรับเฉพาะเลข เช่น `12` `#12` หรือข้อความที่คัดลอกจากป้าย แล้วเปิดแท็บที่คอนเทนต์ชิ้นนั้นอยู่ ไฮไลต์การ์ด และย้ายโฟกัสไปที่ป้ายเลข
ถ้าพิมพ์ผิดหรือไม่พบ จะมีข้อความบอกใต้ช่องค้น (โปรแกรมอ่านหน้าจออ่านให้ · หายเองใน 6 วินาที เมื่อเปลี่ยนหน้า หรือเมื่อกดที่ข้อความ)
บนมือถือ แถวแรกเป็นแท็บ ไอเดีย ร่าง โพสต์ แถวสองเป็นช่องค้นด้วยเลขคู่กับเมนูเครื่องมือ

การ์ดไอเดียรีเสิร์ชแสดง "ไอเดีย N" ซึ่งเป็นเลขแถวในตาราง `marketing_ideas` ไม่ใช่เลขคอนเทนต์ ช่องค้นจึงไม่รับเลขไอเดีย
ร่างที่สร้างจากการ์ดรีเสิร์ช ทั้งกด ร่างโพสต์ ตรงจากการ์ด และผ่าน Studio จากคลังผลงาน จะบอกว่า "จากไอเดีย N" เพื่อตามกลับไปหาแหล่งข้อเท็จจริงได้
ถ้าแก้หัวข้อใน Studio ลิงก์ไอเดียจะหลุด เพราะถือว่าเป็นเรื่องใหม่ ส่วนการเปลี่ยนช่องทางหรือกดร่างใหม่ด้วยหัวข้อเดิมยังคงลิงก์ไว้

Claude หาคอนเทนต์จากเลขได้ด้วยคำสั่งอ่านอย่างเดียว:

```bash
node scripts/marketing-content.mjs list
node scripts/marketing-content.mjs show 12
```

สคริปต์นี้ไม่เขียนกลับ เพราะหน้าเว็บบันทึกเวิร์กสเปซทั้งก้อนทับทุกครั้งที่มีการแก้ การแก้คอนเทนต์จึงทำที่หน้า `/marketing` เท่านั้น
เทสต์ของตัวแจกเลขอยู่ใน `npm run test:marketing-content`

ข้อจำกัด: ถ้าเปิดหน้านี้ค้างไว้สองแท็บหรือสองเครื่องแล้วแก้ทั้งสองฝั่ง ฝั่งที่บันทึกทีหลังจะทับของอีกฝั่งทั้งก้อน ซึ่งเป็นข้อจำกัดเดิมของเวิร์กสเปซ
สองแท็บในเบราว์เซอร์เดียวกันใช้ตัวนับเลขร่วมกัน จึงไม่แจกเลขซ้ำ แต่สองเครื่องที่ต่างคนต่างเปิดค้างไว้ยังอาจแจกเลขซ้ำได้ ควรรีเฟรชหน้าก่อนเริ่มแก้บนแท็บหรือเครื่องอื่น
