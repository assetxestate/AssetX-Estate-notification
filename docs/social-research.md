# ระบบรีเสิร์ชโซเชียลและเทรนด์ (social-research) — โปรไฟล์อสังหาฯ ขายฝาก/จำนอง

สร้าง 2 พ.ย. 2569 จากสกิล `social-research` (ต้นแบบ DivisionX Card) **ยกโครง ไม่ยกเนื้อ** — เลน คำค้น คะแนน กติกา เขียนใหม่สำหรับธุรกิจขายฝาก/จำนอง/นายหน้า
เป้าหมาย: ให้ระบบ (และ Hermes ในฐานะ AI ที่เขียนมุมเล่า) ออกไปสำรวจข่าว เว็บทางการ ชุมชน และคู่แข่ง แล้วนำกลับมาเป็น **คิวไอเดีย** ให้เจ้าของเลือกทำคอนเทนต์ที่หน้า `/marketing`

## หลักการที่ห้ามตัด

1. **โค้ดคิดตัวเลข AI แค่เล่า** — คะแนน คัดกรอง กันซ้ำ ทำด้วยกฎใน JS ทั้งหมด AI ได้รับไอเดียที่คิดเสร็จแล้วไปเขียน "มุมเล่า" 3 มุม
2. **ทุกอย่างเข้าคิวให้คนเลือก** — ไม่มีอะไรโพสต์เองหรือแก้ prompt เอง
3. **อ่านอย่างเดียว · ไม่โต้ตอบอัตโนมัติ · แยกจากบัญชีเพจจริงของร้าน**
4. **แยกเลนต่อแหล่ง** — เลนพังไม่ล้มทั้งรอบ · กันซ้ำด้วย `external_key` UNIQUE (นับทุก status) · cap ต่อ (source, subtype) นับรวมคิว
5. **ยึดเนื้อหาจริง** — ไม่มีเนื้อหาจริง = ติดป้าย ⚠️ "ห้ามเดาจากชื่อ" (คลิป YouTube ทุกตัวตอนนี้)
6. **ใช้เฉพาะช่องทางฟรีที่กติกาอนุญาต หรือเจ้าของอนุมัติรับความเสี่ยงไว้ชัดเจน** — UA บอกชื่อบอท · เจอ 429/403/Cloudflare = ข้าม ห้ามเลี่ยง
7. **ไม่เก็บข้อมูลบุคคล (PDPA)** — ตัวลบข้อมูลบุคคลทำงานกับทุกข้อความก่อนบันทึกและก่อนส่ง AI · ฟีดทิ้ง `dc:creator`/`description`/`author` ตั้งแต่ตอนอ่าน
8. **ด่านการเงินในโค้ด** — ดอกเบี้ย/สินไถ่ > 15% ต่อปี · คำ overclaim · "ธปท. อนุญาต" · "0.01%" ผิดเงื่อนไข = บล็อก (ใช้กับร่างคอนเทนต์)

## ภาพรวม

```
07:00 ทุกวัน (Task Scheduler บนเครื่องที่เปิด · เปิดสายก็รันชดเชย เพราะเช็ก "วันนี้รันแล้วหรือยัง")
  node scripts/research-ideas.mjs run
    1 expire    ตั้ง status=expired ให้ไอเดียเก่า (ไม่ลบแถว)
    2 collect   ทุกเลน → ตรวจ subtype → ลบ PII → คะแนน → รวมข่าวซ้ำตามเหตุการณ์ → กันซ้ำ → cap → upsert
    2b enrich   ไอเดียที่มีลิงก์แต่ยังไม่มีข้อเท็จจริง (📌): ดึงหน้าต้นทางด้วยตัวดึงมารยาทเดิม → เอาเนื้อบทความ/คำโปรย → AI สรุป ≤ 7 ข้อ "เฉพาะที่อยู่ในข้อความ" → summary "📌 …" (≤ 15 ลิงก์/รอบ · ดึงไม่ได้ = ⚠️ บอกเหตุผล)
    3 angles    AI (Hermes → Ollama ในเครื่อง → Gemini) เขียน 3 มุมเล่าคนละรูปแบบ ให้ไอเดียที่ยังไม่มี (เขียนทีละแถว)
    3b drafts   AI ตัวเดิมเขียน "ร่างโพสต์เต็ม" ให้ทุกมุมเล่า — เฉพาะไอเดียที่มีข้อเท็จจริง (📌/manual) (เก็บใน angles[i].draft · ≤ 8 ไอเดีย/รอบ · ~1.5–2 นาที/มุมบน 14b) — ดู "ร่างโพสต์เต็มล่วงหน้า" ด้านล่าง
    4 report    สรุปเข้าเทเลแกรมเจ้าของ + เช็กลิสต์แหล่งที่คนต้องดูเองที่ถึงรอบ
        ↓
  ตาราง marketing_ideas (status new) → หน้า /marketing แท็บ "ไอเดีย" (การ์ดรีเสิร์ชขึ้นก่อน เรียงใหม่สุด · แถบสถานะบอกเวลาไอเดียล่าสุดเข้าคิวจาก meta ของ GET · ป้าย "ร่าง AI พร้อม" / "รอร่าง AI" ต่อมุม)
        ↓ เลือกมุมเล่า + ร่างโพสต์ = picked (chosen_angle = มุมที่เลือก) → ร่างเข้าแท็บ "ร่าง" รอตรวจ (ใช้ร่าง AI ของมุมนั้นถ้ามี ไม่มีจึงใช้เทมเพลต) · ทิ้ง = dismissed + เหตุผล
```

ขั้น 2 ล้มเท่านั้นที่นับว่ารอบล้ม (exit 1 · ตั้ง Task Scheduler ซ้ำ 07:30/08:00 ได้ สคริปต์ข้ามเองถ้าสำเร็จแล้ว) · ขั้น 1/3/4 ล้มแค่เตือน ⚠️

```
21:00 ทุกคืน (+ สำรอง 23:00 · เจ้าของเลือกช่วงกลางคืน 3 พ.ย. · ทั้งสองรอบอยู่ในวันไทยเดียวกัน ก่อนเที่ยงคืน · ห่างจากรอบรีเสิร์ช 07:00 และรอบ DVX ~07:03 · เครื่องเดียวกับ Chrome profile Research)
  node scripts/research-social.mjs run      ตัวเฝ้าเพจ Facebook (ขั้น 7) — ใช้ browser + บัญชีสำรองร่วมกับ DivisionX Card
    ตรวจแถวพักร่วม/โควตา → ถือกุญแจกลาง → อ่าน ≤ 4 เพจที่ถึงรอบ (≤ ~7 นาที) → ปล่อยกุญแจ → โพสต์แรงกว่าปกติของเพจ → คิว (source social) → เทเลแกรม
```

### คำตัดสินของเจ้าของ (`owner_decisions` ใน idea_sources.json)

เจ้าของอนุมัติ 2 พ.ย. 2569 ให้ใช้ 4 ทางเดียวกับต้นแบบแม้ robots/ToS ของแพลตฟอร์มห้าม (รับความเสี่ยงเอง): Google News RSS · YouTube channel RSS · yt-dlp · อ่านเพจ Facebook ผ่านบัญชีสำรอง
ตัวเก็บ**ข้ามเลนที่ `allowed` ไม่ใช่ `true`** และพิมพ์บอก · เว็บที่ ToS ห้ามสคริปต์ยังเป็นคนดูเอง

- `server/research/drafts.js` — ต่อจากขั้นมุมเล่า: ทุกมุมที่ยังไม่มีร่าง → AI (ผู้ให้บริการชุดเดียวกับมุมเล่า) เขียน headline · caption · cta · hashtags · `needs_check` (สิ่งที่คนตรวจต้องยืนยัน) จาก "ข้อเท็จจริงที่มี + มุมเล่า + ความจริงของแบรนด์" เก็บที่ `angles[i].draft` ของแถวเดิม (ไม่แก้ตาราง)

## ตัวเฝ้าเพจ Facebook (ขั้น 7) — ใช้ browser ร่วมกับ DivisionX Card

เจ้าของตัดสิน 3 พ.ย. 2569: "เบื้องต้นใช้ร่วมกันไปก่อน" — Chrome profile `Profile 9` (alias OpenCLI `research`) + บัญชีสำรองชุดเดียวกับ DVX · **AssetX ใช้ได้เฉพาะ Facebook** · ข้อตกลงเต็มอยู่ในสกิล
`~/.claude/skills/social-research/profiles/shared-browser-dvx-assetx.md` (ฝั่ง DVX ทำแล้วใน `deploy/agents/shared_browser.py` + `social_watch.py`) · แก้ข้อตกลงฝั่งเดียวไม่ได้ (ข้อ 10 — แก้ทั้ง `shared-browser.mjs` ในสกิล + สำเนาในรีโปนี้ + ฝั่ง Python)

สิ่งที่ตัวเฝ้าเพจทำทุกรอบ (ลำดับตามข้อตกลง 4.6 · เทสต์ครอบทุกข้อใน `social-watch.test.mjs`):

1. **ก่อนรอกุญแจ** — `state.json` ร่วมมีแถวพัก `facebook` ที่ยังไม่ครบ 3 วัน = ไม่เปิด (ไม่ว่าใครเจอ) · `usage.jsonl` มีแถว `assetx` วันนี้ = ข้าม (วันละ 1 รอบ · รอบสำรอง 23:00 ข้ามเอง — ต้องอยู่ก่อนเที่ยงคืนไม่งั้นนับเป็นอีกวัน) · ไม่มีเพจถึงรอบ หรือโควตาเหลือ 0 = ไม่รอ
2. **ถือกุญแจ** `%USERPROFILE%\.research-browser\lock.json` (สร้างแบบ exclusive) รอได้ 20 นาที · ไม่ว่าง = ข้ามรอบและบอกว่าใครถือ · กุญแจที่เงียบเกิน 10 นาที = ยึดได้ (รายงานว่ายึดจากใคร)
3. **ตรวจซ้ำหลังได้กุญแจ** (แถวพัก · โควตา) แล้วตัดเพจตามที่เหลือ: `min(12 − ที่ทุกโปรเจกต์เปิดวันนี้, 4 − ที่ AssetX เปิดวันนี้)`

5. **ทีละเพจ** — จด `usage.jsonl` `{"project":"assetx","pages":{"facebook":1},"result":"open"}` **ก่อนเปิด** → `browser open` → รอ 5.5–7.5 วิ → วน `browser eval FB_JS` + `scroll down 900` ≤ 10 ครั้ง (หยุดที่ 12 โพสต์ / 3 รอบไม่มีใหม่) → เว้น 6–14 วิ · ทุกคำสั่งผ่านตัวห่อ `oc()` ที่แตะสัญญาณชีพ (`lock.require()`) ก่อน · ต่อท้าย `--session assetxwatch --window background --profile research` เสมอ
6. **งบเวลา** — ไม่เปิดเพจใหม่หลัง 5 นาที · ไม่เปิดซ้ำหลัง 6 นาที (ได้ < 3 โพสต์เปิดซ้ำได้ 1 ครั้ง) → ถือกุญแจไม่เกิน ~7 นาที (DVX รอได้ 8) · เพจที่ไม่ได้อ่าน/อ่านได้น้อย = ไม่นับว่าเยี่ยม รอบหน้าได้คิวแรก
7. **โดนบล็อก** (หน้า `/login` `/checkpoint` หรือมีช่องรหัสผ่านแต่ไม่มีโพสต์) → `setBlocked('facebook')` ลง `state.json` ร่วม (DVX พักด้วย 3 วัน) หยุดเลนทันที · อ่านสำเร็จ = `clearBlocked`
   · **หน้าต่างถูกซ่อน** (ต้นเหตุ "เพจละ 1 โพสต์" ที่ DVX หาเจอ 3 พ.ย. 2569 commit 2e6fcdd · ยกมาใส่ 6 พ.ย.): หน้าต่างโหมด background ที่ Windows นับว่าถูกบัง/จอล็อก = `visibilityState` hidden → Chrome หยุดวาด FB ไม่โหลดโพสต์ถัดไปแม้เลื่อนสุด · `FB_JS` คืน `vis` · ซ่อน + ได้ < 3 โพสต์ = `Hidden` → หยุดเลน FB ทันที ไม่เปิดซ้ำ ไม่นับว่าเยี่ยม (13 วิ แทน ~60 วิ/เพจ ไม่เปลืองโควตาบัญชีร่วม) · **ไม่ใช่บล็อก ไม่พัก 3 วัน** · รายงานบอกว่า Chrome ที่รันอยู่มีค่ากันหยุดวาด (`CHROME_FLAGS`) หรือยัง · ตัวเฝ้าเพจเปิด Chrome เองด้วยค่านี้เสมอ · ซ่อนแต่ได้ ≥ 3 โพสต์แล้ว = เก็บเท่าที่มี

9. **หลังปล่อยกุญแจ** — รวมโพสต์เข้าคลังต่อเพจ (แคปชั่นผ่าน `pii.js` ก่อนเสมอ · ไม่เก็บชื่อ/ข้อความคนคอมเมนต์) → โพสต์แรง = `max(eng/median 60 วัน, views/median) ≥ 2` และ `eng ≥ 10` หรือ `views ≥ 3000` และแคปชั่นผ่าน topic gate อสังหาฯ (ฐานต้องมี ≥ 4 โพสต์ — เพจคู่แข่งเล็ก รอบแรก ๆ ยังไม่มีไอเดีย) → `source=social` `subtype=social_fb` คะแนน 4.6–6.2 (+0.3 คู่แข่ง) `external_key=sw:fb:<tid>:<post key>` → upsert ≤ 8/รอบ · คิวโซเชียลค้าง ≤ 20 · ลิงก์ที่มีแล้วไม่ใส่ซ้ำ → เทเลแกรม (เฉพาะรอบที่แตะ browser หรือมีเรื่องต้องบอก)
   · **ร่างโพสต์ AI สำหรับไอเดียจากเพจ** (6 พ.ย. 2569): ข้อความโพสต์ในเครื่องหมายคำพูด “…” ของ summary (ตัดที่ 300 ตัวอักษร · ≥ 40 ตัวอักษร) นับเป็น "ข้อเท็จจริง" ให้ขั้น 3b ร่างได้ (`hasResearchFacts`/`splitFactsNotes` ใน `drafts.js`) · ตัวเลขยอดของเพจไม่ส่งให้ AI เลย · คำใบ้กลุ่มเพจเป็นหมายเหตุถึงผู้เขียน · ชื่อเพจจากป้าย "Facebook · <ชื่อเพจ>" ถูกแทนด้วย "เพจหนึ่ง" ถ้าหลุด · ไม่ใช้โครง "อัปเดตพร้อมที่มา" (ห้ามอ้างเพจ) · ขั้น 2b enrich ไม่แตะลิงก์ facebook.com และไม่เขียนทับ summary ของไอเดีย social

ใส่ค่ากันหยุดวาดในไอคอน Google Chrome ตัวหลัก (รันใน PowerShell แบบ **Run as Administrator** ครั้งเดียว · สำรองไอคอนเดิมไว้ที่ `~/.research-browser/chrome-shortcut-backup` · เจ้าของเลือกทางนี้ 6 พ.ย. 2569 · ระวัง: ตัวอัปเดตของ Chrome อาจเขียนไอคอนทับ ถ้าตัวเฝ้าเพจรายงานว่า "ไม่มีค่า" อีกให้รันซ้ำ):

```powershell
$flags = '--disable-backgrounding-occluded-windows --disable-features=CalculateNativeWinOcclusion'
$backup = "$env:USERPROFILE\.research-browser\chrome-shortcut-backup"; New-Item -ItemType Directory -Force $backup | Out-Null
$sh = New-Object -ComObject WScript.Shell
foreach ($p in "$env:PUBLIC\Desktop\Google Chrome.lnk", "$env:ProgramData\Microsoft\Windows\Start Menu\Programs\Google Chrome.lnk") {
  if (-not (Test-Path $p)) { "ไม่มีไฟล์: $p"; continue }
  $s = $sh.CreateShortcut($p)
  if ($s.Arguments -match 'disable-backgrounding-occluded-windows') { "มีค่าอยู่แล้ว: $p"; continue }
  Copy-Item $p (Join-Path $backup ("backup-" + (Split-Path (Split-Path $p) -Leaf) + "-Google Chrome.lnk")) -ErrorAction SilentlyContinue
  $s.Arguments = ($s.Arguments + ' ' + $flags).Trim(); $s.Save(); "ใส่แล้ว: $p"
}
```

## ประเภทย่อย คะแนน และคิว

- `subtype` ต้องอยู่ใน `idea_sources.json → subtypes` (อายุ · กลุ่ม A–D · cap) ไม่งั้นตัวเก็บปฏิเสธพร้อมคำเตือน
- คะแนน = Σ_กลุ่ม w × min(คำต่างกันที่เจอ, 2) + ความสด (วันนี้ +2 · <3 วัน +1.5 · <7 วัน +0.8 · ≥14 วัน −1) · **topic gate** ต้องเจอคำ transaction/policy/asset อย่างน้อย 1 คำ
- Pantip เพดาน ~5.5 · YouTube เพดาน ~7.5 (คลิปไวรัลไม่กินท็อป) · ธปท. ฐาน 5.0 · ปฏิทิน 4–5.5 · ลีด 4–5 · manual 6
- รวมข่าวเหตุการณ์เดียวกันด้วย `event_key = <subtype>:<วัน>:<คำ policy>` (กนง. 70 ชิ้น → 1 แถว + "สำนักอื่นที่รายงาน") · ซ้ำข้ามรอบภายใน 7 วันไม่ใส่
- หมดอายุ = `status='expired'` เมื่ออายุ > max(14, max_age_days ของ subtype) · `event_date` ยังไม่ถึง หรือมีคอนเทนต์อ้าง = ไม่แตะ

## นโยบายเครดิตและมุมเล่า

- `news` `official` `auction` → ต้องอ้างชื่อสำนัก/หน่วยงาน (+วันที่) ในโพสต์ ห้ามลงเนื้อเต็ม (ฐานเศรษฐกิจ · Bangkok Post · REIC · กรมบังคับคดี บังคับ)
- `community` `youtube` `social` และ subtype `competitor` → ห้ามอ้างกระทู้/ช่อง/เพจ · เล่าเป็นความรู้ทั่วไป
- กติกาต่อ subtype อยู่ `angles.js → SUBTYPE_NOTES` (เช่น auction_npa ห้ามเชียร์ซื้อ · scam ห้ามเอ่ยชื่อ · competitor เรตเป็นโฆษณาไม่ใช่ข้อเท็จจริง)
- ความจริงของแบรนด์จาก `brand_facts.json` เท่านั้น — เติมพื้นที่/ค่าธรรมเนียม/ช่องติดต่อจริงใน `.local/research/brand_facts.local.json`

## กับดักที่รู้

- `event_date` ต้องเป็น ค.ศ. (ใส่ พ.ศ. = อนาคต 543 ปี ไม่หมดอายุตลอดกาล) — ตารางมี CHECK กันไว้ · `calendar.json` มีเทสต์ตรวจรูปวันที่
- ตัวลบข้อมูลบุคคลจับ "คุณสมชาย" (ไม่เว้นวรรค) ไม่ได้ → ฟีดทิ้งฟิลด์ผู้เขียนตั้งแต่ตอนอ่าน
- Google News ห้ามเขียน `when:` ในคำค้น (ตัวเก็บต่อให้) · ใส่ `site:`/วงเล็บซ้อนทำให้ตัวกรองเวลาเพี้ยน
- ชื่อไฟล์ CSV ของกรมบังคับคดีเปลี่ยนทุกเดือน → กุญแจคือ `led:<package>:<YYYY-MM>`
- Bangkok Post ส่ง gzip โดยไม่บอก → `fetcher.js` ถอดจาก magic bytes
- `\w` ใน JS ไม่จับอักษรไทย → regex เลขคดีใช้ `\p{L}\p{M}\p{N}` + flag `u`
- ตัวเก็บต้องไม่รันซ้อน (ล็อกไฟล์ · stale 2 ชม.) · upsert ignore-duplicates ทำให้รันซ้ำปลอดภัย
- `collect --dry-run` ไม่ดูและไม่แสตมป์รอบเวลาเลน (`state.lane_last_run`) — เจอจริง 3 พ.ย. 2569: dry-run เมื่อคืนทำให้รอบจริงแรกได้แค่ 13/34 เลน เพราะเลน daily ถือว่า "รันแล้ว" (เกณฑ์ ≥ 12 ชม.) · ถ้าต้องการให้รอบจริงยิงทุกเลนใหม่ ลบ `lane_last_run` ใน `.local/research/state.json` แล้ว `collect`
- หัวข่าว "ผ่าทรัพย์สิน/บัญชีทรัพย์สิน" ของนักการเมืองเข้าประเภท valuation เพราะคำ "ที่ดิน…เพิ่มขึ้น" → เพิ่มใน `title_drop` แล้ว (รอบแรกหลุดมา 1 ชิ้น เจ้าของทิ้งจากหน้าเว็บได้)
- ชื่อมุม (label) ถูกตัดที่ 22 ตัวอักษรตามกติกาใน prompt — โมเดลในเครื่องชอบเขียนยาวแล้วโดนตัดกลางคำ (เช่น "กฎหมายใหม่ ธปท. 57/256") · ถ้าจะแก้ ให้แก้ที่ prompt หรือ `parseAngles` ไม่ใช่ที่ UI
- `FB_JS` ของ DVX เป็น Python raw string — ในรีโปนี้เก็บเป็นไฟล์ `facebook-page.dom.js` อ่านด้วย `readFileSync` **ห้ามวางใน template literal** (`\/` `\d` `\s` เพี้ยน → ตัวจับหน้า login ตายเงียบ = ไม่มีวันรู้ว่าโดนบล็อก) · เทสต์ตรวจว่า parse ผ่านและข้อความต้นฉบับยังอยู่ · DVX แก้ DOM เมื่อไหร่ รัน scratchpad `extract-fbjs.mjs` ก๊อปใหม่
- URL เพจแบบ `/p/<ชื่อ>-<เลข>/` (เพจที่ไม่มี username) — ต้นแบบได้รหัสเพจ "p" ซ้ำกันทุกเพจ · ที่นี่ใช้เลขท้าย (`fb_61557696524403`) · `permalink.php?story_fbid=` ต้องคง story_fbid ไว้ก่อน hash ไม่งั้นทุกโพสต์ได้กุญแจเดียว
- การใช้ Facebook วันนี้ของบัญชีร่วมดูได้จาก `status` (นับจาก `usage.jsonl` ทุกโปรเจกต์) — DVX มีแถว `result: diagnose` ที่ `pages` ว่าง (เช็ก bridge/ล็อกอิน ไม่เปิดเพจ) ไม่กินโควตา
